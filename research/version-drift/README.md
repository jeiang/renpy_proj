# Why game directories break across Ren'Py 8 versions (ticket #3)

Sources: Ren'Py git (github.com/renpy/renpy). Local blobless clone in `renpy-src/` (gitignored; re-fetch:
`git clone --filter=blob:none https://github.com/renpy/renpy renpy-src && cd renpy-src && git fetch --tags`).
Analysed at tag `8.5.3.26051504` (the 8.5.3 line has several rebuild tags `8.5.3.26042902 … .26051504`; there is no bare `8.5.3` tag, so "8.5.3" = latest of those) and, for history, tags `8.0.1.22070801`, `8.1.3.23091805`, `8.2.3.24061702`, `8.3.7.25031702`, `8.4.1.25072401`, `8.5.0.25111603`.
Nothing here was executed against a running 8.5.3 engine; items marked [INFERENCE] are read from code only. No visual/HITL checks were needed.

## Short answer
1. **The .rpyc "version gate" never trips inside 8.x.** `renpy.script_version = 5003000` (`renpy/__init__.py`) is identical in every 8.x tag checked (8.0.1 → 8.5.3), as are `savegame_suffix = "-LT1.save"` and `BYTECODE_VERSION = 1`. A `.rpyc` whose `data["version"] != script_version` is silently rejected (`renpy/script.py` `load_file`, ~L957); this only hurts pre-8/7.x-era files.
2. **Real breakage is elsewhere:** (a) pickle *layout* of AST nodes changed in 8.4 (one-way: new reads old, old cannot read new); (b) Python 3.9 → 3.12 at 8.4 (game Python source is recompiled from text in the running interpreter); (c) behaviour changes in 00compat that are *only* reverted if `script_version.txt`/`config.script_version` says so, and some changes have no revert switch; (d) saves/persistent are forward-only in practice.
3. **One newer engine can run older 8.x games** via `00compat.rpy` (flag reversion) plus rpyc/pickle back-compat. It cannot run games built on a *newer* engine on an older one. It fails for changes with no compat switch and for games that ship their own native/Python-version-sensitive code.

## 1. .rpyc format
- Container: `RENPY RPC2` header + 3 slot entries (`renpy/script.py` `write_rpyc_header`, `read_rpyc_data`), zlib-compressed pickles; slot 1 = pre-static-transform AST, slot 2 = after; trailing 16-byte md5 of the `.rpy` source + `RPYC_MAGIC`. Loader tries slot 2 then 1; legacy (v1, bare zlib) still readable. Header format unchanged across 8.x.
- Empirical: local game (8.0.1, `game/scripts/ch9/ch9_1.rpyc`): header `RENPY RPC2`, slots (1, off 46), (2, off 119454); slot pickle protocol 2; `{'version': 5003000, 'key': 'unlocked'}`; `renpy.ast.Label` state is a plain dict (`'name'` …), i.e. old layout.
- `PyCode` pickles **source text**, not bytecode (`renpy/ast.py` `PyCode.__getstate__` = `(1, source, (filename, linenumber), mode, py, hashcode, col_offset)`). `__setstate__` accepts 4–7 element tuples. So Python in released games is re-compiled by the running interpreter on each load (cached in `cache/bytecode-<maj><min>.rpyb`, keyed by `importlib MAGIC_NUMBER` + `PYC_MAGIC` suffix; a cache, safe to delete; `BYTECODE_FILE` is per-Python-version since 8.1).
- **8.4 layout change (backward-compatible only one way).** Commit `3af05dadf` (2024-12-30, "cslots: Migrate AST to cslots") is in 8.4 (changelog 8.4.0: "internal representation of the game script … 50% faster"). `renpy/cslots.pyx` writes node state as `(None, slots_dict)` (tuple) and `__setstate__` accepts tuple **or** dict, so 8.4/8.5 read 8.0–8.3 rpyc. Older `Object.__setstate__(new_dict)` (`renpy/object.py`) does `new_dict.pop(...)`, so ≤8.3 given an 8.4+ rpyc would raise. [INFERENCE: from code; not run.] Node also gained `_name/name_version/name_serial` fields. `script_version` was *not* bumped, so nothing gives a clean error.
- Python-2-era rpyc (Ren'Py ≤7): `renpy/compat/pickle.py` `Unpickler` rewrites `datetime` and `_ast` py2 nodes (`REWRITE_NODES`), `PyCode.py=2` triggers `renpy/compat/fixes.py` token fixes (octal, `<>`, backticks…). Ren'Py 7 out of scope; note that `renpy/compat/` is **not** the version-compat layer (that is `renpy/common/00compat.rpy`); it is py2→py3 shims.
- Source-game rpy/rpyc mixing: if both exist, rpyc is used only when `md5(rpy + RPYC_MAGIC)` equals the digest at the end of the rpyc; otherwise the `.rpy` is reparsed and the rpyc rewritten. `RPYC_MAGIC` is `_2025-07-06` in 8.4+; bumps force recompile (source games only; released games have no rpy to fall back to). Pre-8.4 engines used `md5(version_only)`-seeded digests (8.0.1 `Script.__init__`: `hashlib.md5(renpy.version_only…)`). [INFERENCE: exact per-tag magic history not enumerated.]
- Archives: `RPA-3.0` and `RPA-2.0` only handled (`renpy/loader.py` L155/L201); unchanged in 8.x (grep at 8.5.3; older tags not diffed).
- `key` field: games built with `--lock` share a key; mismatch => "does not share a key" exception (`load_appropriate_file`). Not version-related.

## 2. script_version.txt and compat flags
- Launcher (`launcher/game/distribute.rpy` ~L1030) writes `game/script_version.txt` = `repr(version_tuple[:-1])`, e.g. `(8, 0, 1)` (local game confirms) unless the game has `script_version.rpy(c)` or `build.script_version=False`.
- `renpy/common/00compat.rpy`: 
  - `python early hide:` reads `script_version.txt` via `renpy.open_file` → `config.early_script_version`, `early_developer = not script_version`, `safe_text`; sets `config.future_annotations = True` for 8.0.0–8.1.x (8.2.0 reverted: incompatible.rst "Stringified annotations"; games need `rpy python annotations`), `keyword_after_python` for ≤7.2.2.
  - `init -1000` sets `config.script_version` from the file; falls back to reading `renpy/__init__.py` in game base dir for very old games.
  - `_set_script_version(version)` (triggered by any assignment to `config.script_version`, `renpy/defaultstore.py` L102) applies a cascade of `if version <= …:` blocks setting `config.*` flags back to old behaviour. 8.x tiers in the 8.5.3 file: ≤8.4.99 (`images_directory`, `maximum_embiggens=False`, `pygame_sdl2` in store); ≤8.3.99 (`old_show_expression`, `cds_label_callbacks`, `mesh_pad_compat`, `zoom_zaxis`); 8.2.x/7.7.x tiers (`character_callback_compat`, `bubble.*`, `box_reverse_align`, `limit_transform_crop`, `window_functions_set_auto`, `fill_shrinks_frame`, `tts_queue`); 8.1.x tiers (`simple_box_reverse`, `atl_pos_only`, shaper→freetype, `mixed_position`, `drag_group_add_top`, `transitions_use_child_placement`, `interpolate_exprs`, `say_replace_event`, `screens_never_cancel_hide`…); 8.1.1/8.1.2 (`dissolve_shrinks`, tts); 8.0.3 (quadratic volumes, fadeout, sticky layers, constant stores…); 8.0.2/8.0.1 (`modal_blocks_*`); ≤7.4.x older tiers. Everything down to 5.x is present.
  - `RENPY_EXPERIMENTAL` env disables the whole cascade.
- **No `script_version.txt` ⇒ game treated as "current"**: no compat reversion, and `config.early_developer = True`, `safe_text=False`, and (`00library.rpy` L355) `config.developer=True`. Games repackaged/stripped of this file therefore silently get 8.5.3 behaviour + developer mode (and `.rpy`-backup behaviour in `Script.choose_backupdir`, which skips backups only if a script_version file exists).
- Note: `renpy/script.py`'s `choose_backupdir` keys off the same file names.

## 3. Python runtime
- 8.0 ships Python 3.9.10 (changelog "8.0"); 8.1 web uses 3.11, all else 3.9 (changelog 8.1); **8.4.0: "Ren'Py now uses Python 3.12 on all platforms"** (changelog 8.4.0). 8.5.3 `pyproject.toml`: `requires-python = ">=3.12.8,<3.13"`. So 8.0–8.3 = 3.9, 8.4–8.5 = 3.12.
- Effects: game `.rpy`/`.rpyc` Python is recompiled from source, so 3.9→3.12 syntax/stdlib differences apply to *game code* (removed stdlib modules `distutils`, `imp`, `asyncore`; changed `ast`, `collections.abc` aliases already gone in 3.10; 3.12 error locations). [INFERENCE: which specific games break was not tested.] Games that ship `.pyc`/`.pyo`/native extensions built for 3.9 fail (native is out of scope).
- Bytecode cache filename embeds Python major/minor, so a switch just rebuilds cache.

## 4. Save and persistent compatibility
- Save = zip (`json`, `renpy_version`, `log`, `screenshot`) (`renpy/loadsave.py` ~L110-125); `savegame_suffix "-LT1.save"` constant across 8.x. Metadata `_renpy_version`, `_version`. There is **no version check on load**; `loads(log_data)` unpickles the RollbackLog + store. Docs (`save_load_rollback.rst` L13): "While we usually attempt to keep save compatibility between releases, this compatibility is not guaranteed."
- Pickle protocol: `renpy/compat/pickle.py` `PROTOCOL = 2` through 8.3.7; **`PROTOCOL = pickle.HIGHEST_PROTOCOL` from 8.4** (checked 8.4.1, 8.5.3). Python 3.9 can read protocol 5, so mostly OK, but new saves also contain 3.12-era objects. Unpickler: `fix_imports=True, encoding="utf-8", errors="surrogateescape"`; py2 datetime objects fixed up.
- Persistent: 8.4 changed seen-statement/translate keys to 64-bit hashes (`renpy.astsupport.hash64`, `config.hash_seen=True`, commit `0a1e694e0` 2025-01-05; changelog 8.4.0 "Persistent Data"). New engine reads both hashed and plain keys (`seen_label` checks both); older engines won't recognise hashed keys (seen-flags lost, no crash [INFERENCE]).
- Save tokens (`renpy/savetoken.py`): saves from another machine prompt with `gui.UNKNOWN_TOKEN`; `check_load` returns True if no signing keys. Player must supply/keep token dirs or auto-accept.
- Objects in saves are pickled by module path (`renpy.ast.*`, `renpy.python.Revertable*`, store classes); renames/removals in renpy across versions break loads (unverifiable without corpus).
- Also relevant: `renpy/common/00compat.rpy` `_compat_versions` flags act at load time, so a save made under compat A resumes under compat A only if game files same.

## 5. Documented incompatible changes (sphinx/source/incompatible.rst @ 8.5.3; https://www.renpy.org/doc/html/incompatible.html)
Revertable via compat (auto by script_version): most 8.0–8.5 entries (see list §2). **Not revertable / no compat define documented:** 8.5.0 language detection ("en" over "us"); 8.4.1 shader order (now sorted by name); 8.4.0 Python module `__file__` relative paths, automatic oversampling (left enabled for old games by design), LayeredImage variant/prefix parsing + "multiple" group name, small GUI viewport (advice only); 8.4.3-ish 8.3.4 removal of ATL `update` event; 8.2.1 vertical text with harfbuzz ("no compatibility define is provided"); 8.2.0 polar angle clamping, empty ATL block now an error, translate statements no longer call `statement_callbacks`; 8.1.0 keymap rewrite (custom keymaps), Live2D SDK version, Android keystore layout, translate None error (revertable), `renpy.loadable` search prefixes; 8.0.0 platform lib dir rename (`lib/py2-windows-x86_64`), `renpy.exports` unrelated. Live2D 8.5.3 now requires Cubism 5.3 (out of scope). Munge in strings (8.3.0) has `config.munge_in_strings` but is **not** in the 00compat cascade (default True in `renpy/config.py`), so old games get it unless `01nomunge.rpy`. `config.window_next` similarly not cascaded (set in `000window.rpy`).
- Also: some cascade entries are keyed to the *previous* patch release (e.g. `_compat_versions(version, (7,7,99),(8,2,99))`), so games with script_version exactly equal to the fix release (e.g. 8.2.1 for fill_shrinks_frame `(8,2,1)` …) get nuanced handling. [INFERENCE: not each tier tested].
- The docs themselves say: "setting `config.script_version` will cause many of these changes to be reverted, at the cost of losing access to recent features" and "Our intent is that all other changes should not affect existing scripts."

## 6. Where one engine running older 8.x games fails
1. Games without `script_version.txt` (stripped / hand-assembled / 7.x conversions) run in "current" mode plus developer mode.
2. Behaviour changes with no revert (list above): vertical text, language detection, shader order, polar angles, ATL update event, keymap overrides, renderer/text/audio output differences (harfbuzz shaping, log audio volume have flags; the rest are visual/numeric).
3. Game-embedded Python: 3.9→3.12 stdlib/syntax breaks; games bundling `.py` using removed modules (`imp`, `distutils`, `asyncore`), or `renpy.*` internals that were refactored (e.g. `pygame_sdl2` → `renpy.pygame`, aliased in 8.5; store import removed but flagged).
4. Renderer/platform-specific extension modules and `config`-poking games that rely on undocumented `renpy.display.*` internals (any route that reimplements rendering in Rust must reimplement or emulate those APIs; see Implications).
5. Saves/persistent made under other versions (§4) — forward only.

## Adjacent findings
- rpyc slot 2 already contains translate restructuring (static transforms) — cheap to load; slot 1 fallback re-runs `static_transforms` (`renpy.translation.restructure`), i.e. the loader must still run Ren'Py's translation logic.
- 8.4 replaced script AST storage with C-level `cslots` (`renpy/cslots.pyx`), an engine extension module that a non-CPython or Rust implementation must replace (a pickle-compatible Node layer).
- No bare `8.5.3` git tag; use `8.5.3.26051504` (and confirm that matches the SDK download).
- Testing suggestion not done: download SDK 8.0.1/8.3.7/8.5.3 and cross-load real rpyc files headlessly to confirm the forward failure mode in §1 (needs ~GB downloads).

## Implications for the route decision
- Route (c) (stock engine, launcher + shared store): sidestep drift by picking the engine matching `script_version.txt` (released games run natively on their original version); a shared store must key engine distributions by (major.minor) and Python 3.9 vs 3.12 boundaries (8.0–8.3 vs 8.4–8.5) and can't blindly use newest for all. Saves stay valid only when same-or-newer engine is used.
- Routes (a)/(b): the single 8.5.3 baseline is feasible for released 8.0–8.5 games *because* `script_version` is constant and 8.4+ loaders read the old dict layout and the 00compat cascade exists; but the Rust side must (1) implement/host `00compat.rpy` semantics (it lives in Ren'Py's Python-layer script, so route (b) inherits it free, route (a) must port every `config.*` flag and its behaviour), (2) unpickle rpyc in both layouts with Python-side classes (dict and `(None, slots)` tuple), (3) host CPython 3.12 for game Python and accept 3.9-era game code breakage, (4) read `script_version.txt` including its absence semantics.
- Route (a) carries the largest exposure to the non-revertable behaviour list (§5, §6) since each is implemented in engine code that would be reimplemented.
- Everything ticket #12 (decision) needs: drift is *manageable by compat baseline 8.5.3 with `script_version.txt` honoured*, not by engine-version pinning alone; a per-game version pin remains a robust fallback only in route (c).
