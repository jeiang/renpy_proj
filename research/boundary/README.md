# Rust–Python boundary: which modules are replaced, which are rebuilt (ticket #21)

Route (issue #12): a Rust host embeds CPython 3.12 and bundles Ren'Py 8.5.3's Python layer. It rebuilds Ren'Py's Cython as-is and replaces only graphics (wgpu), video, images, text, and window/input/audio (winit + cpal + gilrs). Ren'Py 7 games run through the Python 2 compatibility module.

Source: Ren'Py tag `8.5.3.26051504` (commit `39895c1e`), local clone `research/version-drift/renpy-src` (re-fetch: `research/engine-anatomy/fetch.sh` or the git command in `research/version-drift/README.md`). Every "read" claim below cites a file in that tree; line numbers are for that tag. Anything not observed is marked **[INFERENCE]**. This is research only: nothing here builds the player.

Two throwaway C probes were **run** (`probe/run.sh`, needs the repo devshell plus `nix shell nixpkgs#python312Packages.cython`, Cython 3.2.5, CPython 3.12.14):

1. A host that calls `PyImport_AppendInittab("fakepkg.sub.native", …)` gets a **dotted-name builtin module** that wins over a same-named `.py` on `sys.path`, and Python can subclass a type defined in it (with buffer export). So Rust can supply modules under Ren'Py's dotted names with no files on disk and no `core.py` patch.
2. A Cython module compiled **unmodified** with `from shimpkg.surface cimport PySurface_AsSurface` runs against a **non-Cython** `shimpkg.surface` that only exports a `__pyx_capi__` PyCapsule named `"SDL_Surface *(PyObject *)"`. It reads `w/h/pitch/pixels` from a plain C struct embedded in the object, and a Python subclass of the surface type works. This is the "minimal C Surface shim" option, proven.

## 1. Short answer

- **Nothing in the rebuilt Cython needs SDL or the pygame `Surface` C ABI once text, images and graphics are replaced, with one exception:** `renpy/display/accelerator.pyx::nogil_copy` (a 5-line function used only by `pgrender.copy_surface` and `swdraw`). Verified from the full `cimport` graph (section 3): the only modules that `cimport` `renpy.pygame.surface`/`sdl2` and are *not* themselves replaced are `accelerator`, `ftfont`, `hbfont` (text, replaced), `gl2draw`/`gl2texture` (graphics, replaced), `_renpy` (images, replaced), `assimp` (3D, see decisions), and `renpysound` (replaced).
- **The Python-level `Surface` API is the real coupling, not the C ABI.** Python code subclasses it (`pgrender.Surface(pygame.Surface)`), builds it as `Surface(size, flags, sample_surface|depth, masks)`, takes shared-memory `subsurface`s, and passes it to every image/text/video/screenshot path. Recommendation (section 5): a Rust `#[pyclass(subclass)]` with buffer protocol, plus a one-line patch to `accelerator.pyx`.
- **Draw backend selection has no registry.** `Interface.get_draw_constructors` hard-codes `make_draw("gl2", "renpy.gl2.gl2draw", "GL2Draw", "gl2")` and friends (`display/core.py` L1151-1155). A wgpu backend registers with **zero patches** by supplying the module `renpy.gl2.gl2draw` (class `GL2Draw` + `standard_uniforms`); or with a 1-line patch to add a `"wgpu"` entry (section 6).
- **`00director.rpy` (1913 lines) is referenced by exactly four other engine files** (`00keymap.rpy`, `00compat.rpy`, `_errorhandling.rpym`, `_developer/developer.rpym`); the stub is ~40 lines (section 7).
- **Three small patches to Ren'Py's own files are needed** (all in section 8): `accelerator.pyx` (drop `nogil_copy`/SDL), `gl2model.pyx` (drop the `GLTexture` cimport), and `00director.rpy` (replace). Everything else in the "rebuild" list compiles unmodified.

Consequences:

- Modules that need `SDL_Surface*`/`PySurface_AsSurface` (i.e. read `w/h/pitch/pixels`): **`ftfont`, `hbfont`** (`draw` only: `surf.pixels/pitch/w/h`, `ftfont.pyx` L766-807, L885; `hbfont.pyx` L1096), **`gl2texture`** (upload from `s.pixels/pitch/h`, L446-574), **`gl2draw`** (screenshot readback, L1291-1335), **`_renpy`** (all software image ops), **`accelerator`** (`nogil_copy`). After replacement, `accelerator` is the only survivor.
- **GL2 types the rebuilt modules need:** none, after the two patches. Python (not Cython) reaches `renpy.gl2.gl2draw.standard_uniforms` (`display/transform.py` L1329; a `set[str]` defined at `gl2draw.pyx` L1820) and `renpy.gl2.gl2draw.default_position` (only as a name in `renpy/__init__.py` L262's reload blacklist).
- **The text module's C structs:** `Glyph` and `Line` are `cdef class`es with `public` attributes (`textsupport.pxd`), so Rust can build and read them **through the Python attribute API** with no ABI (each glyph = ~15 setattrs). A faster path is a tiny additive Cython bridge that `cimport`s `Glyph` and fills fields directly. `ftfont`/`hbfont` are not needed by `textsupport`/`texwrap`.
- **Private C data the Rust renderer must read:** `Mesh.point_data/attribute/triangle` are *not* `public` (`gl2mesh.pxd`), so they are invisible from Python. `Render`, `GL2Model`, `Matrix` fields are all `cdef public` (`render.pxd`, `gl2model.pxd`, `matrix.pxd`). A small additive Cython module (`cimport Mesh`, return buffer addresses/`memoryview`s) exposes the mesh arrays with no patch.

## 5. Surface ABI options once SDL is gone

What Python needs from a Surface (from grep of `renpy/**` outside the pygame package): construct `Surface(size, flags, depth | sample_surface, masks)`; **subclass** (`pgrender.Surface`, `pgrender.py` L74-91, overrides `convert_alpha/convert/copy/subsurface`); `subsurface(rect)` sharing pixels with the parent (`pgrender.surface` L94-119 allocates `(w+4, h+4)` and returns the inner `(2,2,w,h)` subsurface so C code can read past the edge); `get_size`, `get_at`, `set_at`, `fill`, `blit`, `convert_alpha`, `copy`, `get_masks`, `get_shifts`, `get_bounding_rect`, `get_rect`, `unlock`; hashable and usable as a dict key (`Renderer.texture_cache[surf]`, `core.py` mutated_surface). Pixel format is RGBA byte order (the masks are read back from a sample surface and sorted, `pgrender.set_rgba_masks` L41-71). `Render.blit` does `isinstance(source, pygame.Surface)`.

| Option | What it is | For | Against |
|---|---|---|---|
| **A. Rust `#[pyclass(subclass)]` `Surface`** (buffer protocol; `Arc` pixel storage + offset/pitch for subsurfaces) | The Python API above implemented in Rust. `__getbuffer__` exports 2-D RGBA8 with stride = pitch (writable). Rust font/images/video/wgpu upload use the struct directly, no GIL, no copies. Patch `accelerator.pyx` (drop `nogil_copy`; `pgrender.copy_surface` L128 calls a Rust `Surface.copy_from` instead). | No SDL, no C ABI to keep; the same buffer feeds `queue.write_texture` (row stride = pitch, no 256-byte alignment needed for `write_texture`), NumPy, `memoryview`. One place to fix pixel-format bugs. | Must implement the full Python API (866-line `surface.pyx` behaviour) incl. subsurface aliasing, sample-surface constructor, and `subclass`+`weakref`. PyO3 supports `subclass` and the buffer protocol [INFERENCE from PyO3 docs; the C-level equivalent is what probe 1 ran]. |
| **B. Minimal C shim: keep `PySurface_AsSurface`** | Rust module named `renpy.pygame.surface` exports a `__pyx_capi__` capsule `"SDL_Surface *(PyObject *)"` returning a pointer to an `SDL_Surface`-shaped prefix `{w, h, pitch, pixels}` inside the Rust object. Stock `ftfont`/`hbfont` compile and run unchanged (they read only those four fields). | **Proven** (probe 2). Gives an early bring-up path: Ren'Py's own text stack runs over the Rust Surface before the Rust text module exists. Zero patches to `ftfont`/`hbfont`/`gl2texture` reads. | Needs SDL headers at compile time (`sdl2.pxd` is `cdef extern from "SDL2/SDL.h"`); `accelerator.nogil_copy` still needs `SDL_UpperBlit` (patch it out anyway); the Rust object layout becomes an ABI (struct prefix must stay put); only useful while stock text is kept. |
| **C. Keep `renpy/pygame/surface.pyx` + SDL2 linked for surfaces only** | Build the stock Cython Surface without the video subsystem. | Zero behaviour risk; every consumer unchanged. | Keeps SDL2, SDL2_image, libpng/libjpeg in the tree and link line; pixel ops stay C not Rust; contradicts "SDL is gone". Fallback only. |
| **D. Pure Python or NumPy-backed Surface** | | Easy | Too slow for per-frame text/image paths. Rejected. |

**Recommendation:** A as the end state; B as the temporary bring-up if stock text runs first. With A, the boundary carries no C ABI at all. The patch list is tiny: `accelerator.pyx` (5 lines) and `pgrender.copy_surface` (1 line).

## 6. How `renpy.display.draw` is selected (backend registry)

There is no registry; it is a hard-coded factory in `renpy/display/core.py`:

1. `Interface.set_mode()` (L1231-1271) takes `draws = [("current", renpy.display.draw)]` if one exists, else `self.get_draw_constructors()`, then loops: `draw.init(virtual_size)`; the first that returns true is assigned to **`renpy.display.draw`** (L1255) and `renpy.display.render.models = draw.info["models"]`.
2. `get_draw_constructors()` (L1093-1169) reads the requested name from `renpy.game.preferences.renderer`, overridden by env `RENPY_RENDERER`, overridden by `renpy.session["renderer"]`. Valid names are only those in the platform list: Windows `["gl2","angle2","gles2"]`, mobile/web `["gles2"]`, Linux aarch64 `["gles2","gl2"]`, else `["gl2","gles2"]`; `"sw"` is appended as a last resort (also forced by `safe_mode`).
3. `make_draw(name, module, cls, *args)` (L1129-1149) does `__import__(module); getattr(sys.modules[module], cls)(*args)` inside `try/except` that logs "Couldn't import {name} renderer". The four registrations are L1151-1155 (`gl2`, `angle2`, `gles2` → `renpy.gl2.gl2draw.GL2Draw(name)`; `sw` → `renpy.display.swdraw.SWDraw()`).
4. Later code type-checks against `SWDraw` (`core.py` L3128, L3140) and reads `renpy.display.draw.info`.

**Options to register wgpu:**

| Option | How | Trade-off |
|---|---|---|
| **1. Supply the module `renpy.gl2.gl2draw`** (recommended) | Register `renpy.gl2.gl2draw` as a Rust builtin (probe 1) exporting `GL2Draw` (constructor takes the name string; `init(virtual_size)`) and `standard_uniforms`. `core.py` is untouched; `"gl2"` becomes the wgpu backend. | No patch to Ren'Py files. The name `gl2` stays in `log.txt` and in the Preferences renderer picker; there is no separate "wgpu" preference value. `angle2`/`gles2` map to the same class (harmless). |
| 2. One-line patch | add `make_draw("wgpu", "renpy_rs.draw", "WgpuDraw")` and put `"wgpu"` in the `renderers` lists. | Clean naming and persisted preference; a patch in a file that changes across Ren'Py releases. |
| 3. Post-import monkey patch | replace `Interface.get_draw_constructors` after `renpy.display.core` loads. | No file patch but brittle across releases. |

Also required: delete/disable `sw` (its `SWDraw.init` calls `pygame.display.set_mode` with no window system): `safe_mode` and the "sw last hope" path would otherwise reach it. With option 1, an `SWDraw` init failure is logged and ends in `raise Exception("Could not set video mode.")` (L1265), which is acceptable.

Because `GL2Draw.init` drives the window, `pygame.display.*` (window/size/caption/icon/hints/drawable size), and event delivery are one Rust object graph (winit window created lazily by the first `display.set_mode`/`GL2Draw.init`).

**Stub design** (drop-in file `renpy/common/00director.rpy`, same name so `.rpyc` caches and init ordering match):

```renpy
init offset = -1101

default persistent._director_bottom = False    # keep the persistent field identical

init python in director:
    _constant = True                           # not part of saves, as today (00compat sets it too)
    from store import Action
    # inert copies of every documented config knob, so `define director.X = ...` never NameErrors
    tag_blacklist = { "black", "text", "vtext", "side" }; scene_tags = { "bg" }; show_tags = set()
    transforms = [ "left", "center", "right" ]; transitions = [ "dissolve", "pixellate" ]
    audio_channels = [ "music", "sound", "audio" ]; voice_channel = "voice"
    audio_patterns = [ "*.opus", "*.ogg", "*.mp3" ]; audio_channel_patterns = { }
    button = True; spacing = 1; director_spacing = 0; other_spacing = 0; viewport_height = 280

    class _State(object):
        active = False; show_director = False; mode = "lines"
    state = _State()                            # `director.state.show_director` is read by user code in the tutorial

    class Start(Action):
        def __call__(self):
            renpy.notify(_("The interactive director is not enabled here."))   # existing translated string
        def get_sensitive(self):
            return False
    class Stop(Action):
        def __call__(self):
            return None
```

Notes: `Start` mirrors the stock guard for "not enabled here" (`00director.rpy` L708-713) and never calls `_reload_game()`; `renpy.arguments.register_command("director", …)` (L340) is dropped (no CLI for a player); nothing else (line log, screens, `config.line_log*`) is touched, so behaviour outside developer mode is unchanged. If the stock `00director.rpyc` is present it must be deleted/ignored, since the `.rpy` digest mismatch would recompile it (`rpyc` magic check, see `research/version-drift`): ship the stub already compiled. The licence status of this file is issue #27 and outside this note.

## 8. Loose ends that affect the boundary

### 8.1 Registering Rust modules under Ren'Py's dotted names
Probe 1 proved `PyImport_AppendInittab("a.b.c", …)` works with `import a.b.c as x`, `from a.b import c`, and wins over `a/b/c.py`. Packages themselves (`renpy`, `renpy.pygame`, `renpy.text`, `renpy.gl2`, `renpy.audio`) stay real directories; only leaf modules are Rust. `renpy.__init__.Backup` (used by `reload_all`, L268-372) skips by name: `renpy.pygame*`, `renpy.text.ftfont/hbfont/bidi`, `renpy.tfd`, `renpy.gl2` (the package itself) are already blacklisted; other Rust modules (`renpy.audio.renpysound`, `renpy.gl2.gl2draw`, `_renpy`) would be pickled by `Backup.backup_module` (functions/classes pickle by reference, so probably fine) **[INFERENCE, not run]**; this only matters for developer Shift+R reload.

### 8.2 Things not in the interface list but in the way
- **`renpy.pygame.rwobject.RWopsIO`** is Ren'Py's whole file layer (`loader.py` L36, L497: `open_file = RWopsIO`; used by RPA archive reads L594-609). Pure Python (`io.RawIOBase` over a file with `base`/`length`, `from_buffer`, `from_split`) suffices, so this is off the Rust critical path.
- **`presplash.py`** opens its own `pygame.display.Window`; drop or port separately.
- **`RENPY_TEST_RWOPS`** path in `loader.py` L499-520 is a test hook.
- **`renpy.gl2.live2d`** imports `live2dmodel` inside `try/except ImportError` (L14-16), so Live2D degrades cleanly without Cubism; `defaultstore.py` L184/L187 still reads `renpy.gl2.live2d.Live2D` and `renpy.gl2.assimp.GLTFModel`, so both modules must import.

### 8.3 3D models (`GLTFModel`)
`renpy.gl2.assimp` cimports `RWopsFromPython`, `sdl2`, and imports `GL2Model` at module level (L101), so it cannot be rebuilt as-is once SDL/GL go. Options: (i) out of milestone 1, ship a tiny Python `assimp` stub defining `GLTFModel` (raises "unsupported"), `free_memory`, `preload`, `finish_predict`, `loader`, `loader_lock` (the names `core.py` L1183, `im.py` L515, `predict.py` L212, `__init__.py` L260-261 touch); (ii) keep assimp with a Rust RWops shim. Not investigated further.

## Implications for the route decision

- The Surface ABI does not block the route. After graphics, text, images, video, audio are Rust, exactly **one** rebuilt Cython function (`nogil_copy`) touches `SDL_Surface*`; drop it with a 5-line patch. If a bridge is wanted during bring-up, probe 2 shows a Rust object can satisfy stock Cython's `PySurface_AsSurface` with a `__pyx_capi__` capsule.
- The genuine coupling is the **Python** Surface API (subclassable, shared-memory subsurfaces, sample-surface constructor). It fits a Rust `#[pyclass(subclass)]` with buffer protocol, whose memory also feeds wgpu uploads. Size the images/text tickets around this class.
- "Rebuild as-is" holds unpatched for 20 modules plus the generated `style_*functions` (`astsupport`, `cslots`, `lexersupport`, `pydict`, `style`+`styledata`, `encryption`, `tfd`, `matrix`, `render`, `quaternion`, `filter`, `textsupport`, `texwrap`, `gl2polygon`, `gl2mesh`, `gl2mesh2`, `gl2mesh3`, and the two `styledata` shims); two (`accelerator`, `gl2model`) need a one-liner each; everything GL/SDL/FFmpeg/FreeType is replaced.
- Backend registration is free: provide `renpy.gl2.gl2draw` and `core.py` needs no change. Keeping `GL2Model`/`Mesh2` on the CPU side means the wgpu renderer receives ready-made cropped meshes and only needs the Cython bridge to read `Mesh` buffers.
- A GPU-YUV video path has a precedent contract (the web branch of `video.py`) that returns a texture object rather than a Surface.
- `00director.rpy` replaces cleanly; the stub is ~40 lines.

## Decisions the user still needs to make

- **D1 Surface strategy.** A (Rust `Surface`, patch `accelerator`) end state; take B as a bring-up (stock text over the Rust Surface) or go straight to A with Rust text?
- **D2 Backend registration.** Module-replace `renpy.gl2.gl2draw` (no patch, name stays "gl2") or a 1-line `core.py` patch to add a real "wgpu" name (Preferences picker, log text)?
- **D3 Patch policy for "as-is".** OK to carry three small patches to Ren'Py files (`accelerator.pyx`, `gl2model.pyx`, `00director.rpy`), or must the bundled layer be byte-identical (then `nogil_copy` and the `GLTexture` isinstance become shims: B for the former; for the latter provide a stub `gl2texture` module exporting `GLTexture`)?
- **D4 3D models and Live2D in milestone 1.** Stub `assimp` (recommended) or carry a Rust RWops shim?
- **D5 Text bridge speed.** Rust builds `Glyph`/`Line` through Python attributes (no ABI) or through an additive Cython bridge writing C fields (faster, needs the Cython build to expose it)?
- **D6 Video hook.** Accept a 2-line patch to `display/video.py` so a Rust texture (GPU-YUV) is taken on non-web platforms, or make `read_video` return a `Surface` (CPU convert) and accept the cost?
- **D7 Ship the stub `00director.rpy`** pre-compiled, or run Ren'Py's parser to compile `renpy/common` at build time (rpyc digests)?
