# Ren'Py 8.5.3 GL2 renderer on wgpu, and a GLSL 1.20 translator (ticket #22)

Question: how do Ren'Py 8.5.3's model renderer (meshes, textures, render-to-texture, clipping, `renpy.register_shader` parts and uniforms, mipmaps, `config.mesh_oversample`) map onto wgpu, with headless rendering for streaming? What must a translator do to get game GLSL 1.20 / ESSL 1.00 into something naga accepts? Which existing translators can be reused?

Output: a mapping table (section 3), a translator approach (section 4) with a working prototype and probe results (sections 4.3, 5), and implications (section 7).

## 0. Sources, tools, how to reproduce

- Ren'Py source: tag `8.5.3.26051504` at `research/version-drift/renpy-src` (main checkout). Paths and line numbers below are relative to that tree. `fetch.sh` clones it if absent.
- `extract_shaders.py <renpy-src>`: pulls every shader part Ren'Py registers itself (`renpy/common/_shaders.rpym`, `renpy/common/00textshader_ren.py`, `renpy/gl2/live2d.py`; 25 parts) with `ast`, assembles full GLSL 120 and ESSL 100 programs exactly as `renpy/gl2/gl2shadercache.py:218-264` does, and writes them to `battery/generated/` (gitignored: derived from Ren'Py text).
- `battery/edge/`: 16 hand-written user-shader pairs (e01-e15, e19 a trivial control) that exercise known GLSL 1.20 to 4.50 hazards (committed).
- `translator-probe/` (Rust, naga 30.0.1): the translator prototype (`src/translate.rs`) and a harness that runs naga parse + validate + WGSL-out + MSL-out over a battery. Output in `out/translator-*.txt`.
- `wgpu-probe/` (Rust, wgpu 30.0.1, headless, no surface): runs the translated shaders on a real device and checks coordinate space, mip selection, sampler and blend validation, uniform packing, cold compile cost, and 1080p readback. Output in `out/wgpu-probe.txt`. Run from `wgpu-probe/` after `extract_shaders.py`.
- Machine: Apple M3 Pro, Metal, wgpu backend Metal (`out/wgpu-probe.txt`). Only Metal was exercised; D3D12 and Vulkan results are [INFERENCE].
- Tools used via `nix shell nixpkgs#glslang nixpkgs#spirv-cross nixpkgs#spirv-tools` (glslang 16.4.0): see 4.1. Everything else via `nix develop -c`.
- No game was run for this ticket (no fact needed one). The test corpus has no custom shaders (`research/test-corpus/README.md` line 15), so the shader battery is Ren'Py's own 25 parts x {120, 100} plus my edge cases. That is a bounded sample, not the wild population.

## 1. How the GL2 renderer is layered (what the Rust host must own)

Python (stays): shader-part registry and shader source assembly (`gl2shadercache.py`: `register_shader`, `ShaderPart`, `source()`, `ShaderCache.get`, `config.shader_part_filter`), text shaders (`renpy/text/shader.py`), `Render`/`Transform` uniform and property plumbing. The interface the Cython/C layer must satisfy is therefore: `Program(partnames, vertex_src, fragment_src)`, `Variable`, and the draw-context calls below.

Cython (replaced by Rust in milestone 1):

| Ren'Py file | Role | Lines |
|---|---|---|
| `gl2/gl2draw.pyx` | `GL2Draw` (window, FBOs, `draw_screen`, `load_all_textures`, `render_to_texture`, `is_pixel_opaque`, `screenshot`), `GL2DrawingContext` (matrix/uniform/property/clip state, `draw_one`, `draw_model`), `draw_render` | 1825 |
| `gl2/gl2shader.pyx` | `Variable` parser, `Program.load/draw` (attribute binding, uniform setting, blend and color-mask state) | 424 |
| `gl2/gl2uniform.pyx` | Uniform `Setter`s (per GLSL type), `Getter`s (`u_transform`, `u_time`, `tex0`, `res0`, `__premul`, `__inverse`, ...), `Sampler2DSetter` (wrap/filter/anisotropy per draw) | 735 |
| `gl2/gl2texture.pyx` | `TextureLoader`, `GLTexture` (surface upload, premultiply, render-to-texture, mipmaps, tiling of over-size images) | 727 |
| `gl2/gl2mesh*.pyx`, `gl2polygon.pyx`, `gl2model.pyx` | Mesh2/Mesh3 storage, layouts, CPU clipping (`crop`), `GL2Model` | ~1800 |
| `gl2/assimp.pyx`, `live2dmodel.pyx` | GLTF loading (Assimp), Live2D (proprietary Cubism Core). Out of scope here; their shaders are in the battery and translate. | |
| `renpy/uguu/*` | GL binding layer. Game scripts import `GL_*` constants from `renpy.uguu` (e.g. `gl_blend_func`, `gl_texture_wrap` values, `sphinx/source/model.rst`, sections "Blend Functions" and "GL Properties"), so a Python module exporting the integer constants must survive. | |

The whole GL2 draw path is three ideas: (1) a depth-first walk of the `Render` tree that accumulates matrices, shader-part lists, uniform dicts, GL properties and a clip polygon (`gl2draw.pyx:1617-1757`); (2) per-`GL2Model` draw of one indexed triangle list with one program (`draw_model`, 1542-1580; `Program.draw`, `gl2shader.pyx:327-391`); (3) render-to-texture for every child of a `mesh` Render, drawn into a shared FBO then `glCopyTexImage2D`'d out (`gl2texture.pyx:352-431`). There is no stencil, scissor, multisample, or geometry/compute shader use: `grep` for `Stencil|Scissor|BlendColor|LineWidth|PolygonMode` in `gl2/*.pyx` finds nothing.

## 2. Values worth knowing (8.5.3 defaults)

`config.gl_lod_bias = -0.6` (`config.py:1188`; the docs say -0.5), `config.mipmap = True` (1143), `config.max_mipmap_level = 1000` (1093), `config.mesh_oversample = 1.0` (1583), `config.depth_size = 24` (1054), `config.max_texture_size = (4096, 4096)` (1100), `config.gl_clear_color = "#000"` (896), `config.nearest_neighbor = False` (644). `auto_mipmap = draw_per_virt < 0.75` (`gl2draw.pyx:641`).

`mesh_oversample`: `load_all_textures` computes `oversample = clamp(hypot(reverse.transform(1,1))/sqrt(2), 1.0, config.mesh_oversample)` (`gl2draw.pyx:1131-1133`) and passes it to `render_to_texture`, which scales the texture size by it (`gl2texture.pyx:373-381`). At the default 1.0 it is a no-op; it needs nothing renderer-specific beyond honouring texture size.

## 4. The GLSL 1.20 / ESSL 1.00 translator

### 4.1 Existing tools: what they do and do not cover

| Tool | Result | Verdict |
|---|---|---|
| naga `glsl-in` 30.0.1 | Accepts only `#version 440\|450\|460` (`front/glsl/parser.rs:267`); rejects loose `uniform sampler2D` (`declarations.rs:448` "variable qualifier"). Accepts everything after source rewriting (4.3). | Use as the back half. |
| glslang 16.4.0 (`glslang -V`) | Rejects `#version 120`: "Desktop shaders for Vulkan SPIR-V require version 140 or higher"; rejects `#version 100`: "ES shaders for SPIR-V require version 310 or higher"; rejects loose uniforms ("non-opaque uniforms outside a block: not allowed when using GLSL for Vulkan") and unbound samplers, even with `--aml --amb`. `-G` (OpenGL SPIR-V) failed to parse its built-ins in this build ("'double' : not supported with this profile"). | Would need the same source rewriter as naga; its only extra value would be stricter GLSL semantics. It is a C++ dependency; SPIR-V into wgpu needs naga `spv-in` anyway. Not chosen. |
| shaderc | Wraps glslang; same limits [INFERENCE from README-level knowledge, not run]. | Not chosen. |
| SPIRV-Cross | Converts SPIR-V **to** GLSL/MSL/HLSL only (`README.md` "Features"). Not a front end. | Irrelevant for ingesting GLSL 1.20. |
| ANGLE translator | Input is GLSL ES 1.00/3.00 (README: "translation from OpenGL ES 2.0, 3.0 and 3.1"; translator "targets Desktop GLSL, Vulkan GLSL, Direct3D HLSL, and even ESSL"), BSD-style [INFERENCE on license]. | Rust GLSL parsers (`glsl`, `glsl-lang`) | Not evaluated (no network search done here). | [INFERENCE] could replace my token-level rewriter with an AST rewriter if the rewriter's bug surface grows. |

### 4.2 What a translator must do (each item found from source, then checked by the prototype)

Ren'Py hands the backend two complete GLSL strings per program (`Program(name, vertex, fragment)`, `gl2shadercache.py:371`): variable declaration lines (sorted by name, only variables a stage mentions), then user functions, then `void main() { ...parts by priority... }`.

1. **Version and preamble.** Drop `#version`, `#extension`, `precision` statements and `lowp/mediump/highp/invariant`; emit `#version 450`. The ESSL preamble `#ifdef GL_FRAGMENT_PRECISION_HIGH` block reduces to nothing.
2. **`uniform` non-sampler variables into one std140 block** (`set 0, binding 0`), union of both stages, sorted by name, identical in VS and FS so one bind group serves both. Packing rules that measurements forced:
   - `mat2` fails in a std140 block (naga: "unsupported matrix of the form matCx2 ... wgpu#4375"); store as `vec4` (columns packed) and rewrite uses to `mat2(u.xy, u.zw)`.
   - `bool/bvecN` are not host-shareable: store as `int/ivecN`, rewrite uses to `(u != 0)` / `notEqual(u, ivecN(0))`.
   - **Arrays of `float/int/bool/vec2/ivec2/bvec2` must be widened to one `vec4`/`ivec4` slot per element and indexed `.x/.xy`.** Without it naga's WGSL-text route rejects the module, and the naga-IR route builds a pipeline but **Metal silently draws nothing** (probe: constant-colour fragment shader with only `uniform float u_w[5];` in the block leaves the target at the clear colour; `vec3[3]` alone is fine). With widening the probe renders the expected pixel (179,191,128,255 vs expected 178.5,191,127.5,255). Ren'Py's `ArraySetter` sends tightly packed data (`gl2uniform.pyx:200-289`); the host repacks.
   - Reserve translator-owned members `renpy_flip_y` and `renpy_target_size` at the end of the block.
3. **`sampler2D` uniforms split** into `texture2D name_t` + `sampler name_s` (set 1, bindings `2i`, `2i+1`); rewrite `texture2D(S, ...)` to `texture(sampler2D(S_t, S_s), ...)`, `texture2DLod/Proj/ProjLod` likewise. The combined form fails in naga (`output.txt` in `research/gpu-media`). A sampler passed to a **user function** (`vec4 f(sampler2D s, ...)`) is handled by cloning the function per distinct sampler argument (prototype does this; edge e02 passes and pipelines build).
4. **Vertex-stage `texture2D`** has implicit LOD 0 in GLSL 1.20; naga has no implicit-LOD sampling in the vertex stage, so emit `textureLod(..., 0.0)` (edge e08; pipeline builds on Metal).
5. **`attribute` to `layout(location = n) in`** (n = index among sorted names; host receives the table), **`varying` to `out`/`in`** with locations from the union of both stages. Emulate GL's link check: a fragment varying with no vertex declaration is an error (prototype returns "link error", as `glLinkProgram` would).
6. **`gl_FragColor`** to `layout(location=0) out vec4`; **`gl_FragCoord`** to a global corrected for y origin; `discard`, `gl_FrontFacing`, `gl_FragDepth` pass through naga. Fixed-function built-ins (`gl_Color`, `gl_ModelViewMatrix`, ...) exist only in desktop 1.20, are illegal in Ren'Py's ES path, and are rejected with "Unknown variable" (edge e13): acceptable, report clearly.
7. **Entry-point epilogue**: rename `main` to `renpy_main`; the wrapper `main` calls it and (vertex) sets `gl_Position.z = (z + w) * 0.5; gl_Position.y *= renpy_flip_y`.
8. **Identifier hygiene.** GLSL 4.50 reserves words that are ordinary names in 1.20 (`sample`, `filter`, `input`, `output`, `patch`, `common`, `uint`, ...) and defines built-ins a 1.20 shader may define itself (`round`, `trunc`, `sinh`, `inverse`, `isnan`, ...). The prototype renames every user-defined top-level function and every identifier in a reserved list (`rp_` prefix; swizzles after `.` untouched). Edge e04 (`float round(float)`, `float sinh(float)`, `float sample`, `vec4 filter`) translates and builds.
9. **Implicit conversions** (`float a = 1;`, `vec2(1)`, `float * int`, `const float K = 2;`) and array constructors are accepted by naga's GLSL 4.5 front end (edge e06), so no rewrite is needed. `mod(x, y)` is lowered to `x - y * floor(x / y)` (`front/glsl/builtins.rs:1943-1968`), i.e. GLSL semantics, not WGSL `%` (edge e01 shows the `floor` in the WGSL).
10. **Non-uniform derivative/implicit-LOD sampling** is accepted (section 3, last row).
11. **Cross-part globals.** Ren'Py concatenates parts into one `main`, so variables declared in one part are visible in others (`model.rst` lines 224-227; `live2d.flip_texture` writes a `varying` declared only in its own `variables` and consumed by `renpy.texture`). Translating the assembled program (not parts) preserves this.

### 4.3 Prototype and results

`translator-probe/src/translate.rs`: token-level lexer plus rewriter (~450 lines, no GLSL AST). Input: the two strings Ren'Py assembles. Output: two `#version 450` sources plus reflection (uniform list, sampler list, attribute locations, varying locations).

- Ren'Py built-ins: **all 25 parts x {GLSL 120, ESSL 100} = 50 of 50 programs** translate, parse in naga, validate, and emit WGSL and MSL (`out/translator-builtins.txt`). That includes `renpy.blur` (loops with `break`, biased sampling), all ten text shaders, the four Live2D parts, `renpy.imagedissolve`, `renpy.mask`, `renpy.alpha_mask`. Mean wall time to translate one program: 0.04 ms.
- Edge battery: **15 of 16** pass naga (`out/translator-edge.txt`; the counts there are per pair). The 16th is e13 (`gl_Color`), an intentional reject.
- On a device (`out/wgpu-probe.txt`): all 25 built-in combos create Metal render pipelines (T11); edge pairs e01-e05, e08, e12, e14, e15 create pipelines through both the naga-IR route and the WGSL-text route (T8).
- Rendering checks against expected pixels: texture shader, y-flip, mip bias, uniform packing (T2, T3, T3b, T5, T10) all exact except level-1 mips generated by blit, max 1/255 off a CPU box filter (T4).

Not covered by the prototype or its tests: `attribute` arrays, uniform arrays of `mat2/mat3/mat4`, user-defined structs holding samplers, preprocessor `#define` macros that collide with reserved names, ESSL-only `#extension` semantics, and real-world community shaders (none in our corpus). The `glsl` / `glsl-lang` route in 4.1 is the fallback if the token rewriter proves too fragile.

## 5. Headless rendering for streaming

- No surface is needed: adapter with `compatible_surface: None`, `Rgba8Unorm` render target, `copy_texture_to_buffer` (rows padded to 256 bytes; 1920 wide is exactly 7680 = 30 x 256, so no padding at 1080p), `map_async`, `device.poll(wait)`.
- Probe T9: clear + copy + map of a 1920x1080 target, 120 sequential frames, no pipelining: **0.44 ms/frame** (2263 fps) on an M3 Pro (unified memory). That is the readback floor, not a render benchmark; a discrete GPU pays a PCIe transfer [INFERENCE].
- For WebRTC the readback need not be a CPU round trip: the streaming ticket decides whether frames go to an encoder as GPU textures (VideoToolbox/NVENC/VAAPI interop) or via this readback + CPU H.264/VP8. This ticket only shows the readback path is cheap enough on Apple silicon.
- `screenshot`, `is_pixel_opaque`, and `translate_point` remain synchronous CPU-visible operations.

## 6. Risks and unknowns

- Cold pipeline creation (median 135 ms on Metal, T11) will cause visible hitches the first time a shader/blend/target combination appears: precompile the `shaders.txt` combos and the blend/target permutations at load. wgpu's `PipelineCache` is Vulkan-only [INFERENCE].
- Anisotropic filtering semantics differ (section 3, sampler row): a visual-quality decision, needs a human comparison (HITL).
- D3D12 and Vulkan were not exercised: the widened-array rule (item 2) was discovered because Metal silently drops draws; other backends may fail differently or loudly. Re-run `wgpu-probe` there before trusting it.
- The uniformity relaxation depends on a naga constant. If a future naga enforces it, sampling inside varying-dependent branches (e.g. `if (mask.a > 0.0) texture2D(...)`) would fail validation; the fix would be `textureSampleGrad` with derivatives hoisted to uniform control flow [INFERENCE].
- Bit-exactness against Ren'Py's GL output (premultiply rounding, mip filter on odd sizes, bilinear tie behaviour) was not measured; only structural equality and <=1/255 mip differences.
- Visual parity of real games under the new renderer is unverified (no computer-use capture available): HITL.

## 7. Implications for the build

1. **Renderer scope is bounded and mostly mechanical.** GL2 is: a tree walk, one indexed draw per model, RTT, CPU mesh clipping, and per-draw uniform/sampler/blend state. Nothing in it (no stencil, scissor, MSAA, geometry shaders) lacks a wgpu equivalent. The pure-CPU parts (matrices, polygons, mesh crop, uniform getters, pixel-perfect) port 1:1 to Rust; the GPU parts reduce to pipeline construction, a mip-blit helper, sampler caching, and a uniform ring buffer.
2. **Ship the translator as a Rust module in the host, translating the assembled program, not the parts.** Keep Ren'Py's Python shader-part assembly. Prototype passes 50/50 built-in programs and 15/16 edge cases; production work is the untested list in 4.3, error messages in Ren'Py's `ShaderError` style, and a shader-battery regression test run in CI.
3. **Use naga's GLSL front end plus a source rewriter; do not adopt glslang, shaderc, SPIRV-Cross, or ANGLE.** The first two refuse the same inputs naga does, SPIRV-Cross is output-only, ANGLE is an ES-only C++ dependency.
4. **Make these choices up front (all measured):** RTT renders directly into the destination texture with a per-pass Y flip and Z remap in the vertex epilogue; uniform arrays are widened to `vec4` slots; `mat2` is stored as `vec4`; `MIN/MAX` blends force `One, One`; anisotropy conflicts with nearest mip filtering; texture format is `Rgba8Unorm` everywhere.
5. **Pipeline cache key** = (program, blend 6-tuple, color mask, cull/front-face, depth on/off, target format). Expect ~135 ms per cold key on Metal; warm from `shaders.txt` at load and show a loading state rather than hitching in a scene.
6. **Pin `wgpu` and `naga` to the same major.** 30.x changed `RequestAdapterOptions`, error scopes, and buffer-map APIs during this probe; the uniformity relaxation and the `mod` lowering are naga behaviours to regression-test.
7. **Streaming**: the offscreen `Rgba8Unorm` target is the frame source; readback costs 0.44 ms per 1080p frame on Apple silicon, so the encoder path (ticket on LAN streaming) is the real constraint, not the renderer.
8. **Follow-ups (HITL / other tickets):** visual parity of real games; D3D12/Vulkan/Linux-software-adapter runs of `wgpu-probe`; choice between trilinear+aniso and no aniso; whether premultiply moves into the decoder (Images ticket); community-shader corpus (none available here).
