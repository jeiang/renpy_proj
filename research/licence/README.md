# Licence audit for a possible public release (ticket #27)

Question: what does a public binary release of the route-(b) player owe to the licences of everything it bundles or links, and which choices would block it? Research date 2026-09-29. **This is not legal advice**: it states what the licence texts and project docs say. Claims not read from a primary source are tagged **[INFERENCE]**.

Sources are linked, not vendored. `./fetch.sh` re-downloads the licence texts and crates.io metadata into the gitignored `upstream/`. Ren'Py source is the 8.5.3 tag (`8.5.3.26051504`) in `research/version-drift/renpy-src` (`git show <tag>:<path>`); the extracted tree used for greps was `/tmp/rp853` (not kept). Extra tools: `nix shell nixpkgs#cargo` (cargo metadata/tree only, nothing built), `python3`.

Scope of "bundled": the route decision (issue #12) is one Rust binary embedding CPython 3.12, Ren'Py 8.5.3's Python layer (`renpy/*.py`, `renpy/common`), and Rust replacements for the Cython/C layer (wgpu, FFmpeg 7+, image loading, text, window/input, audio, WebRTC). Games are user-supplied and never redistributed by us, so game licences are out of scope.

## 1. Result in five lines

1. **Nothing in the intended stack forces a GPL or non-commercial licence on the player, provided four choices are made** (section 4): FFmpeg built **without** `--enable-gpl`/`--enable-nonfree` and shipped as replaceable shared libraries; `renpy/common/00director.rpy` **excluded**; LGPL leftovers of Ren'Py's C layer (fribidi, `sysfont.py`, `SDL_gfxPrimitives`) **not carried over**; CPython from a build without readline/gdbm.
2. **One real trap inside Ren'Py itself.** `00director.rpy` is licensed for **non-commercial use only** (file header), which Ren'Py's own licence page does not mention (it says "most of Ren'Py is MIT"). Shipping it makes the player non-free for downstream commercial use.
3. **LGPL is the only copyleft that reaches the shipped binary** (FFmpeg; Ren'Py's own statement that games "must be distributed in a manner that satisfies the LGPL"). It is manageable with shared libraries + source offer + notices.
4. **Permissive with notice duties:** everything else (CPython PSF, wgpu/naga, str0m, HarfBuzz-family, dav1d, SDL, Rust crates) needs licence-text/notice reproduction only. MPL-2.0 (symphonia, certifi, webrtcsink) is file-level copyleft and only bites if we modify those files.
5. **Patents are a separate axis** and no licence audit closes it: H.264/HEVC are the exposed formats; VP8/VP9/AV1 come with royalty-free patent grants (with defensive termination).

## 3. Details that carry the decisions

### 3.1 FFmpeg: what flips LGPL to GPL, and what is unredistributable
- Default: LGPL v2.1+; "Some optional parts ... GPL v2+ ... you have to explicitly pass `--enable-gpl` ... FFmpeg's license changes to GPL v2+" (`LICENSE.md:1-11`). The GPL parts are listed at `LICENSE.md:13-50` (many `libavfilter` filters such as `vf_eq`, `vf_hqdn3d`, `vf_boxblur`, `vf_stereo3d`, and x86 asm `flac_dsp_gpl.asm`, `idct_mmx.c`), so **filters are the accidental way to pull in GPL**: keep the filter list explicit (`--disable-filters`, then enable `scale`/`format`/`aresample`-class only).
- GPL external libraries (`configure:2015-2029`): avisynth, frei0r, libcdio, libdavs2, libdvdnav, libdvdread, librubberband, libvidstab, **libx264, libx265**, libxavs, libxavs2, libxvid. Enabling any requires `--enable-gpl`.
- Version-3 libs (`configure:2037-2047`): gmp, libaribb24, libastcenc, liblensfun, opencore-amr, vo-amrwbenc, mbedtls, rkmpp: force `--enable-version3` (LGPL v3). Not fatal, but it adds the LGPLv3 installation-information clause; avoid unless needed.
- Non-free (`configure:2031-2035`): decklink, **libfdk_aac**, libmpeghdec: `--enable-nonfree` → binary "unredistributable" (`LICENSE.md:118-127`). **Never** for a public build.
- Decoders in FFmpeg itself (native H.264, HEVC, VP9, AV1 hwaccel glue, Opus, AAC) are LGPL: **decoding H.264/AAC needs no GPL library**. Only x264/x265 *encoders* pull GPL; hardware encoders (VideoToolbox, NVENC, AMF, VAAPI, QSV, Media Foundation) do not.
- Ren'Py's own precedent: stock builds use FFmpeg 4.3.1 with `--disable-all --disable-everything` plus an allow-list; decoders `mpeg1video ... vp9, libaom_av1`, no H.264/HEVC (`research/gpu-media/README.md:14-17`); `renpy-build` links it statically (`tasks/ffmpeg.py:82,215` `--enable-static`) and satisfies LGPL §6a by publishing `renpy/renpy` and `renpy/renpy-build` (`license.rst:85-92`).

### 3.2 LGPL v2.1 mechanics for a Rust binary
LGPL 2.1 §6 lets a "work that uses the Library" be distributed under terms of your choice **provided the terms permit modification for the customer's own use and reverse engineering for debugging** (`license.rst:396-399`, embedded LGPL text), with prominent notice, licence copy, and one of: (a) complete corresponding source of the Library plus the "work that uses the Library" as object code/source "so that the user can modify the Library and then relink", (b) "a suitable shared library mechanism" that uses a copy present on the user's system, or (c) a written offer for three years.
- **Static linking FFmpeg into the single Rust binary triggers §6a**: we would have to ship relinkable objects (the rlibs) as well as FFmpeg source, and it forbids EULA clauses against reverse engineering. **[INFERENCE]** This is legally possible for a public repo (shipping the source of the player satisfies it), but it constrains a future closed release.
- **Shared `libav*` libraries (DLL/dylib/so) next to the executable** is what FFmpeg's checklist recommends and satisfies §6b on Linux and macOS/Windows in practice [INFERENCE: §6b(1) wording says "already present on the user's computer system"; bundled-next-to-the-exe is the common reading, but it is the more conservative case]. Cost: the one-binary goal becomes one binary + a few shared libraries. Do not rename them to obfuscated names (`legal.html` checklist).

### 3.3 Patents (not covered by the licences)
- FFmpeg's FAQ: "We do not know, we are not lawyers ... [H.264, MPEG-4 statements]" ([legal.html](https://ffmpeg.org/legal.html)); FFmpeg licence LGPL/GPL says nothing that grants patent rights for H.264/HEVC/AAC.
- VP8/VP9 (libvpx `PATENTS`), AV1 (AOM Patent License 1.0 in dav1d `doc/PATENTS`, `license.rst:1743-1850`) carry royalty-free patent grants with defensive termination.
- Streaming to browsers: [INFERENCE] VP8/VP9/AV1 hardware/software encode covers browsers without an H.264 grant. H.264 through OS hardware encoders (VideoToolbox, MF, NVENC) leaves patent licensing with the platform vendor per their terms; not verified here. OpenH264's BSD licence covers copyright only; Cisco's patent cover applies only to Cisco-built binaries [INFERENCE from OpenH264 licence, binaries clause not read].

### 3.4 Copyright headers Ren'Py expects us to keep
- `license.rst:32-34`: "Please see each individual source file for a list of copyright holders." Preserve headers in bundled `.py`/`.rpy`. Files with no header (`renpy/sl2/__init__.py`, `renpy/gl2/__init__.py`, generated `emoji_trie.py`, `linebreak.pxi`, `gl2functions.py`) are generated stubs or tiny glue [INFERENCE: covered by "most of Ren'Py" MIT].
- The Ren'Py third-party list (`license.rst:36-83`) is for the *stock* binary. Our binary has a different list; we must maintain our own (`THIRD_PARTY_LICENSES`) rather than copy theirs (it includes stock-only items like Assimp, ANGLE, libusb, zsync, py2exe).

## 4. Choices that would block a public release, and the safe choice

| Choice | Effect | Safe choice |
|---|---|---|
| FFmpeg configured with `--enable-gpl` (x264/x265/GPL filters) | Whole FFmpeg (and the player linking it) becomes GPL v2+ (`LICENSE.md:9-11`) | Allow-list decoders/filters/hwaccels, no `--enable-gpl`; hardware encoders only; VP8/VP9 via libvpx (BSD) if a software encoder is needed |
| FFmpeg `--enable-nonfree` / libfdk-aac | "Unredistributable" | Native AAC decoder (LGPL); never fdk |
| Static-linked LGPL FFmpeg without relink materials | LGPL §6 violation | Shared libs (recommended) or ship rlibs + source + relink instructions |
| Shipping `00director.rpy` | Non-commercial-only file inside the bundle | Exclude and patch the four references; or ask Ren'Py's author for a relicense; or reimplement |
| Keeping fribidi, `sysfont.py`, `SDL_gfxPrimitives` | LGPL pieces in the player's own code | Rust replacements (`unicode-bidi`, `fontdb`, drop primitives) |
| PBS pre-2023 with readline/gdbm | GPL v3 dependency (`pbs docs/running.rst:333-338`) | PBS 3.12.14 (libedit, no gdbm) |
| FreeType under its GPLv2 option | GPL | Use FTL (credit clause) |
| Cargo dep with only a copyleft option | none in probe | `cargo deny check licenses` in CI with allow-list |
| Bundling Live2D Cubism Core | proprietary, not redistributable | never bundle |
| Twemoji/CC-BY missing attribution | licence breach | Ship `TwemojiCOLRv0.txt` and credit in About |

## 5. Rust dependency licence probe

`probe/Cargo.toml` (never built) lists a realistic candidate set: wgpu 30, naga 30 (`glsl-in`), winit 0.30, str0m 0.24, cosmic-text 0.19, harfrust 0.13, swash 0.2, unicode-bidi, unicode-linebreak, image 0.25, symphonia 0.6 (all codecs), cpal 0.18, pyo3 0.29, ffmpeg-next 9, dav1d 0.11, opus 0.4. `analyse.py` walks `cargo metadata` normal-dependency edges (dev/build excluded); output in `licences-probe.txt`, run summary in `crates.txt` (crates.io metadata for ~50 candidates).

- **447 shipped crates, 30 distinct licence expressions.** No GPL, AGPL, SSPL, BUSL, or proprietary term without a permissive alternative.
- Copyleft-shaped items: 16 crates **MPL-2.0** (all `symphonia*`, file-level copyleft); `r-efi` (`MIT OR Apache-2.0 OR LGPL-2.1-or-later`) and `self_cell` (`Apache-2.0 OR GPL-2.0-only`): choose the permissive option. Non-standard: **WTFPL** (`ffmpeg-next`, `ffmpeg-sys-next`, bindings only).
- Notice-heavy: `aws-lc-sys` (ISC AND Apache-2.0 AND MIT AND BSD-3-Clause ..., no OpenSSL term), `avif-serialize`/`ravif`/`rav1e` (BSD-2/3 + AOM patent grant via AV1), `libfuzzer-sys` (`(MIT OR Apache-2.0) AND NCSA`, appears through an image-codec chain; check whether it is a normal dep or an optional feature), Apache-2.0-only crates (winit, cpal, ab_glyph, unicode-linebreak, spirv, ...).
- The probe covers Rust deps only; C libraries linked through `*-sys` crates (FFmpeg, dav1d, Opus, FreeType if used, PBS Python's own dependencies) must be added by `cargo about`/`cargo deny` plus a hand list. Windows/macOS/Linux target-specific deps are unioned (cargo metadata without `--filter-platform`).

Repeatable: `cd probe && cargo metadata --format-version 1 > /tmp/meta.json && python3 ../analyse.py /tmp/meta.json`.

## 6. Ren'Py's statements vs. the source tree (discrepancies worth knowing)
- `license.rst:7` says "Most of Ren'Py is covered by the terms of the following (MIT) license"; it does not mention `00director.rpy` (non-commercial) or `00console.rpy` (WTFPL).
- `license.rst:47` says Freetype is "Zlib License"; FreeType's own docs say FTL or GPLv2 (`docs/FTL.TXT`). Do not copy Ren'Py's attribution list verbatim.
- `license.rst:29-30`: "Portions of Ren'Py are derived from source code that is licensed under the GNU Lesser General Public License, so Ren'Py games must be distributed in a manner that satisfies the LGPL." In the 8.5.3 Python tree the only LGPL file is `renpy/pygame/sysfont.py`; the rest of the LGPL is in the C layer (FFmpeg, fribidi, `SDL_gfxPrimitives`, libusb, pygame_sdl2 parts) that Milestone 1 replaces.

## Implications for the build

1. **The "avoid GPL-only core dependencies" constraint is satisfiable.** No chosen component requires GPL. The player itself can be MIT OR Apache-2.0 (or MIT); LGPL applies to FFmpeg alone.
2. **FFmpeg policy is the single big decision:** build a project-owned LGPL FFmpeg 7+ (no `--enable-gpl`, no `--enable-nonfree`, no `--enable-version3` unless required), explicit decoder/hwaccel/filter allow-list (kill GPL filters), ship as shared libraries with the configure line and source tarball next to the binary. This gives up "one file", not the licence. Add a CI check that `avutil_license()` (or `ffmpeg -L` equivalent) reports "LGPL version 2.1 or later" **[INFERENCE: check API name]**.
3. **Exclude `renpy/common/00director.rpy`** and remove its four references (`00keymap.rpy`, `00compat.rpy`, `_developer/developer.rpym`, `_errorhandling.rpym`) in the engine-patch set; record it in the patch library as "licence patch". Ask upstream about relicensing if the Director is wanted.
4. **Do not carry over LGPL C/Python pieces** (fribidi, `sysfont.py`, `SDL_gfxPrimitives`); Rust replacements are all MIT/Apache.
5. **Choose the Python build with licences in mind:** PBS 3.12.14 (libedit, no gdbm); ship its licence texts and CPython's PSF notice plus a modification summary if CPython is patched.
