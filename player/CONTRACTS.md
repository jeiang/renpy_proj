# Player workspace contracts

Shared interfaces between the crates in `player/`. The design is in [`ARCHITECTURE.md`](../ARCHITECTURE.md); the facts behind it are in `research/boundary`, `research/pypack`, `research/renderer`, `research/images` and the `prototype/video-proto` branch. Ren'Py source: tag `8.5.3.26051504`.

Change a contract only in this file, in the same commit as the code that needs it.
## Working rules

- One slice, one worktree: `git worktree add .worktrees/build-<slug> -b build/<slug>` from `main`. Commit only there, with Conventional Commits. The coordinator merges with `--no-ff` and pushes.
- Edit only the paths your slice owns. Put new dependencies in your crate's own `Cargo.toml`, not in `[workspace.dependencies]`. Propose contract changes in your final report; do not edit this file.
- `research/` is reference only. Ren'Py source for reading: `/Users/aidanp/Projects/renpy_proj/research/version-drift/renpy-src` (tag `8.5.3.26051504`).
- Game runs follow `research/CONVENTIONS.md` (machine lock, scratch saves, SIGKILL sweep, `traceback.txt` check). Screen capture is allowed for windows you launched.


## Toolchain

- Build shell: `nix develop .#player` (repo root `flake.nix`). It provides Rust, pkg-config, libclang, Python 3.12 with Cython 3.2, LGPL FFmpeg 7.1 (`$FFMPEG_LGPL`, dev output on `PKG_CONFIG_PATH`), FreeType, HarfBuzz, SDL2 headers and static zlib. Never link the GPL `ffmpeg` from the default shell.
- Third-party sources are fetched by scripts into the gitignored `player/upstream/`. Build outputs that are not Cargo's go into the gitignored `player/build-out/`.
- pyo3 0.29 for Python-facing crates, pyo3-ffi 0.29 in `pyhost` and `engine`. The final binary links the static `libpython3.12.a` built by `pyhost`. `pyhost/build.rs` writes a pyo3 config file (`player/build-out/cpython/pyo3-config.txt`, `shared=false`). Every Cargo command in the workspace sets `PYO3_CONFIG_FILE` to it (`player/.cargo/config.toml` `[env]`). Until that file exists, crates can be checked with `PYO3_PYTHON=python3.12`.

## Module registration

Every crate that supplies Python modules exports:

```rust
pub fn inittab() -> Vec<(&'static std::ffi::CStr, unsafe extern "C" fn() -> *mut pyo3_ffi::PyObject)>;
```

Each entry is a **dotted** module name (for example `c"renpy.pygame.surface"`) and its init function. `player` collects all tables and passes them to `pyhost`, which calls `PyImport_AppendInittab` before `Py_InitializeFromConfig`. `pyhost` installs a `BuiltinSubmoduleImporter` (as `renpy-build`'s `runtime/site3.py` L73-90), so a dotted builtin wins over a same-named `.py` file inside a package loaded from a zip. Packages (`renpy`, `renpy.pygame`, `renpy.gl2`, ...) stay real Python packages; only leaf modules are builtins.

## `pyhost`

- `build.rs` (or a script it calls) builds CPython 3.12.8 static from python.org source on macOS, following `research/pypack/build_cpython_static.sh` and its five listed faults. The builtin C modules are the full set in `research/pypack/README.md` §4 and "Implications" item 10.
- API:
  - `pub struct Config { pub inittab: Vec<(&'static CStr, InitFn)>, pub zips: Vec<(&'static str, &'static [u8])>, pub argv: Vec<String> }`
  - `pub fn run(cfg: Config, main_module: &str, main_func: &str) -> anyhow::Result<i32>`: isolated `PyConfig` (`utf8_mode=1`, `site_import=0`, empty `sys.path`), frozen `encodings`, blob importer over every zip (each zip mounted as a `sys.meta_path` finder; earlier zips win), then `import main_module; main_module.main_func()`. It returns the exit code and prints the Python traceback on failure.
  - `pub static STDLIB_ZIP: &[u8]`: the 3.12 stdlib minus tests/tk/idlelib/lib2to3/ensurepip/distutils.
- The blob importer sets `__file__` on modules to `<zip name>/<path>` and serves `get_data()` for package resources.

## `engine`

- `player/engine/fetch.sh` fetches Ren'Py `8.5.3.26051504` source into `player/upstream/renpy-8.5.3/`.
- `player/engine/patches/*.patch`: unified diffs against that tree, applied in name order by the build. Each file starts with a comment that states its reason.
- `player/engine/python/`: pure-Python files added to or replacing files in the layer (same relative paths as in the `renpy` tree, plus the `_player` package).
- `player/engine/extra/**/*.pyx`: additive Cython modules, built with the rest (for example `renpy/gl2/gl2meshbridge.pyx`, owned by `gfx`).
- The build cythonizes and compiles the kept modules (research/boundary §2.1, with the `accelerator` and `gl2model` patches), the generated `style_*functions`, the `extra/` modules and, for bring-up, the stock `renpy.text.ftfont`, `renpy.text.hbfont` and `renpy.text.bidi` (against FreeType, HarfBuzz and the SDL2 headers; they reach pixels only through the capsule below; `bidi` uses the fribidi-free fallback if one exists, else it is built from the stub in `python/`). Everything is one static library.
- API:
  - `pub fn inittab()`: every Cython module.
  - `pub static LAYER_ZIP: &[u8]`: `renpy/**/*.py` from the patched tree plus `python/`, as unchecked `.pyc` (`mkzip.py` style). It includes `_player/boot.py`.
  - `pub static COMMON_ZIP: &[u8]`: `renpy/common`, including the `.rpyc` files compiled at build time. Build-time compile runs the Ren'Py parser inside the embedded interpreter. Until that works, the zip holds `.rpy` only and the runtime compiles into the per-game cache dir.
  - `pub const BUILD_FINGERPRINT: &str`: a hash of the Ren'Py tag, the patches and `python/`. It keys per-game caches.
- `_player.boot.main()` reads its settings from `sys.argv`: `--game <dir>` and `--data <player data dir>`, plus optional `--renderer`. It sets up the virtual `renpy_base`: `renpy/common` is served from `COMMON_ZIP` through `renpy.loader` callbacks, and the six direct-path uses are patched (research/pypack §4). It sends saves to `<data>/saves/<game key>`, and `.rpyc` and bytecode output to `<data>/cache/<game key>/<BUILD_FINGERPRINT>`. It never writes into the game folder and never reads `game/cache`. Then it runs `renpy.bootstrap.bootstrap(renpy_base)`.
- Required patches (the minimum for M1): `accelerator.pyx` (drop `nogil_copy`/SDL), `gl2model.pyx` (drop the `GLTexture` cimport), `display/core.py` (add `make_draw("wgpu", "renpy.gl2.wgpudraw", "WgpuDraw")` and make `"wgpu"` the first renderer on every platform), `display/video.py` (see Video), `00director.rpy` (stub from research/boundary §7), the `renpy_base`/`commondir` direct-path uses, and the `.rpyc` and bytecode output redirect. Pure-Python stand-ins in `python/`: `renpy/pygame/{rect,color,locals,error,rwobject}.py` (constants keep SDL2 numeric values) and `renpy/gl2/assimp.py` (stub).

## `surface` (Python: `renpy.pygame.surface`, `renpy.pygame.image`, `renpy.pygame.transform`, `renpy.pygame.draw`, `_renpy`)

- `Surface` is `#[pyclass(subclass, weakref, dict)]` with the Python API in research/boundary §5 (sample-surface constructor, shared-memory `subsurface`, `get_size/get_at/set_at/fill/blit/convert_alpha/copy/get_masks/get_shifts/get_bounding_rect/get_rect/lock/unlock`, hashable). Pixels are RGBA8 premultiplied or not, as stock does. Masks are `R=0x000000ff, G=0x0000ff00, B=0x00ff0000, A=0xff000000` (little-endian RGBA bytes). It uses the buffer protocol (2-D, stride = pitch, writable).
- Capsule shim: module `renpy.pygame.surface` has a `__pyx_capi__` dict with `PySurface_AsSurface` → a `PyCapsule` named `"SDL_Surface *(PyObject *)"`, which returns a pointer to an `SDL_Surface`-layout struct kept inside the object and valid while it lives (research/boundary probe 2, `research/boundary/probe/shim`). Its `format` points at a static `SDL_PixelFormat` with the masks above. Stock `ftfont`/`hbfont` draw text through it.
- Rust API for other crates:
  - `pub struct PixelView<'a> { pub width: u32, pub height: u32, pub pitch: usize, pub bytes: &'a [u8] }`
  - `impl Surface { pub fn with_pixels<R>(&self, f: impl FnOnce(PixelView<'_>) -> R) -> R; pub fn from_rgba(width: u32, height: u32, rgba: Vec<u8>) -> Self; pub fn generation(&self) -> u64 }`. `generation` changes on every write, so `mutated_surface` can re-upload.
- M1 scope for `image`/`transform`/`draw`/`_renpy`: every function research/boundary §4.5 lists must exist. `pygame.image.load` decodes PNG, JPEG and WebP. Unsupported formats raise `pygame.error` with a clear message, never return blank pixels.

## `platform` (Python: `renpy.pygame.display`, `event`, `key`, `mouse`, `time` (`pygame_time`), `joystick`, `controller`, `power`, `scrap`)

- The API in research/boundary §4.4. Event ids, key codes and modifier values are SDL2's.
- The winit event loop runs on the main thread in pump mode (`EventLoopExtPumpEvents::pump_app_events`). Python's `pygame.event.get/poll/pump/wait/peek` pump it, so Ren'Py keeps its own main loop.
- Rust API for `gfx`:
  - `pub fn create_window(width: u32, height: u32, title: &str, resizable: bool) -> anyhow::Result<std::sync::Arc<winit::window::Window>>`: creates the one window (or returns and resizes the existing one).
  - `pub fn window() -> Option<std::sync::Arc<winit::window::Window>>`
  - `pub fn drawable_size() -> (u32, u32)`: physical pixels.
- `pygame.display.set_mode`, `get_window`, `get_size`, `get_drawable_size` and `Window` all use this one window. `presplash` must not open a second window (stub it to a no-op).

## `media` (Python: `renpy.audio.renpysound`; video frames)

- The full function list in research/boundary §4.1. `file` arguments are Python file objects (from `renpy.loader.load`); read them through Python `read`/`seek`, or through `.name` plus the `base`/`length` of `RWopsIO` when available. FFmpeg decodes (LGPL build), cpal plays, and the mixer runs `renpy.audio.filter` through the function pointer exported by the additive `renpy/audio/filter_ptr.pyx` (owned by `media`, built by `engine` from `player/engine/extra/`).
- Video decode follows `prototype/video-proto` (VideoToolbox hwaccel, software fallback, NV12/P010/yuv420p/p10/444 planes, with no swscale).
- Rust API for `gfx`:
  - `pub enum PlaneLayout { Nv12, P010, Yuv420p, Yuv422p, Yuv444p, Yuv420p10, Yuv422p10, Yuv444p10 }`
  - `pub struct ColorInfo { pub full_range: bool, pub matrix: Matrix /* Bt601 | Bt709 | Bt2020 */ }`
  - `pub struct VideoFrame { pub width: u32, pub height: u32, pub layout: PlaneLayout, pub color: ColorInfo, pub planes: Vec<Plane>, pub pts: f64 }` with `pub struct Plane { pub data: Vec<u8>, pub stride: usize, pub width: u32, pub height: u32 }`.
  - `#[pyclass] pub struct PyVideoFrame(pub std::sync::Arc<VideoFrame>)`: returned by `renpysound.read_video(channel)` (or `None`).

## Video hook (engine patch, M1)

`display/video.py` `get_movie_texture`: when `renpysound.read_video` returns a `PyVideoFrame`, it calls `renpy.display.draw.load_video_frame(frame, mipmap)`. That returns a texture object (see `gfx`), and the rest follows the existing `get_movie_texture_web` branch (`get_size()`, `subsurface(rect)` for side masks, the `renpy.alpha_mask` shader for mask channels).

## `gfx` (Python: `renpy.gl2.wgpudraw`, and stand-ins for `renpy.gl2.gl2draw`, `gl2texture`, `gl2shader`, `gl2uniform`, `renpy.uguu.gl`, `renpy.uguu.uguu` so `renpy.import_all()` succeeds)

- `WgpuDraw` implements the `renpy.display.draw` surface in research/boundary §4.2 and §6. `init(virtual_size)` creates the window through `platform::create_window` and the wgpu device (Metal on macOS). `info["renderer"] = "wgpu"`, `info["models"] = True`.
- Textures: `load_texture(surf, transient, properties)` returns a Python subclass of the rebuilt `renpy.gl2.gl2model.GL2Model` that holds a Rust texture handle (research/boundary §4.2). Images larger than the max texture size become a `Render` of tiles, as stock does. `load_video_frame(frame, mipmap)` uploads the planes and runs YUV-to-RGB on the GPU (WGSL from `prototype/video-proto` `src/shader.wgsl`) into an RGBA texture.
- Shaders: the GLSL that `renpy.gl2.gl2shadercache` assembles is translated with the source rewriter from `research/renderer/translator-probe` and naga's GLSL front end. Uniform arrays are widened to vec4 (Metal otherwise drops draws), and pipelines are cached and precompiled at load.
- Meshes: the additive `renpy/gl2/gl2meshbridge.pyx` (owned by `gfx`, in `player/engine/extra/`) exposes `Mesh` point, attribute and triangle buffers as memoryviews.
- The stand-in `gl2draw` exports `GL2Draw` (its `init` returns `False`), `standard_uniforms` (the set from stock `gl2draw.pyx` L1820) and `default_position`.

## `player`

`player <game-dir> [--data <dir>]` (the default data dir is the platform app-data folder `renpy-player`). It collects the `inittab()` of `engine`, `surface`, `platform`, `gfx` and `media`, mounts `LAYER_ZIP`, `COMMON_ZIP` and `STDLIB_ZIP`, and runs `_player.boot.main`. The exit code is the game's.
