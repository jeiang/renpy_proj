# Synthetic integration corpus

Small test games for CI. Every pixel, sound and script comes from this repository (generated by `build.py` files or written
by hand). No third-party game material is in git or in the build output. The games reproduce the cases that the real-game gate
covers, so a CI job can run `harness/gate.py` on them without any commercial game.

The real-game gate stays manual on the Mac and on artemis (user decision). Issue: #40.

## Games

| Folder | Corpus key | Engine (stock) | What it covers |
|---|---|---|---|
| `story/` | `SynthStory` | Ren'Py 8.5.3 | Dialogue (several characters, narrator, text tags), menus (three, with `set` and conditions), `renpy.input`, generated backgrounds and sprites, `default` state of many types (int, str, list, dict, set, class instance, Character) checked after every load, save and resume. |
| `media/` | `SynthMedia` | Ren'Py 8.5.3 | Images in PNG, JPEG, WebP, AVIF and GIF, each checked in the game against a generated lossless reference PNG (`game/reference/`). Movies: VP9 + Opus, H.264, Theora and AV1 clips (one still picture repeated, so a shot does not depend on timing). |
| `text/` | `SynthText` | Ren'Py 8.5.3 | Kerning, ligatures, right-to-left text (Hebrew, Arabic, mixed lines), outlines, very large and very small text, variable fonts (needs `fetch.sh fonts`; the game falls back to DejaVu Sans without them), text tags, ruby, justify. |
| `view/` | `SynthView` | Ren'Py 8.5.3 | Viewport padding: an odd screen size (1277x719) and a view that is smaller than the window, so the letterbox bars have odd width. A flat pattern with 1 px frames, colour bars, a circle and corner markers shows any off-by-one. |
| `aniso/` | `SynthAniso` | Ren'Py 8.5.3 | Anisotropic textures (`gl_anisotropic`), the existing A/B game. CI runs the six-shot plan `ci.plan`. It has no menu, so its tier is `route` only. |
| `py7/` | `Synth7` | Ren'Py 7.4.11 (Python 2) | Python 2 `.rpyc` files compiled by the 7.4.11 SDK at build time. See [Ren'Py 7](#renpy-7-games). |
| `py7patch/` | `Synth7Patch` | Ren'Py 7.4.11 (Python 2) | A port patch (patch library): one node that only Python 2 runs, and the patch that replaces it. |

## Ren'Py 7 games

`py7/build.py` copies the committed `.rpy` scripts, compiles them with the Ren'Py **7.4.11 SDK** (`renpy.sh <game> compile`,
x86_64 Python 2: Rosetta on an Apple Silicon Mac, native on Linux), then deletes the `.rpy` files. What remains is a
released-style game: `.rpyc` files made by Python 2, as the real corpus games are. The `.rpyc` files are build output
(`harness/testgames/build/`, gitignored). They differ from one build to the next, so nothing depends on their hashes.

`py7/loose/` holds files that are copied as they are after the compile: the player's parser and import hook must read them, so
they must not be compiled by the SDK. Stock 7.4.11 reads them itself when the gate runs.

Every case prints its result with `say` statements. The gate stores a hash of each executed line, and the player run must
produce the same hashes as the stock run (`--baseline`). So each rule is proved by the same Python 2 result that the stock
engine gives.

| Case | Script | Rule |
|---|---|---|
| Integer division, `/=`, `round()` half away from zero, `cmp()`, `long`, `unichr` | `rules_math.rpy` | `division`, `round`, `cmp`, builtins |
| `keys()`/`values()`/`items()` as lists, `map`/`filter`/`zip` as lists, `iteritems`, `iterkeys`, `itervalues`, `has_key`, `sorted(cmp=)`, `list.sort(cmp=)` | `rules_containers.rpy` | `list-*`, `iter*`, `has_key`, `sorted`, `sort` |
| `__metaclass__`, `__nonzero__`, `next`, `__div__`, `__cmp__`, `__eq__` without `__hash__` | `rules_classes.rpy` | class rewrites |
| `exec "..."` in a function, `exec code in ns`, locals set by `exec` | `rules_exec.rpy` | `exec-in-function` (and the `exec` statement through py2fix) |
| Backticks, `<>`, old octal, `10L`, `ur""`, `raise E, v`, `except E, e`, tuple parameters | `rules_syntax_values.rpy` | py2fix |
| `print` statements: plain, `print >>f, x`, trailing comma then a bare `print >>f`, a trailing-comma loop, in a loose module | `loose/legacy_mod.py`, `rules_legacy.rpy` | py2fix and the import hook for loose `.py` files |
| Mixed-type ordering in two init blocks and two story blocks of one file (`sorted([3, "a", None])`, `1 < "a"`, `max(1, "a")`) | `rules_ordering.rpy` | error-driven ordering fix with retry |
| Python 2 save state: `long`, byte `str`, `unicode`, `set`, classic class, `OrderedDict`, tuples, nested containers | `rules_state.rpy` | saves made by stock 7.4.11 (`saveresume`) load; an after-load check raises if a value differs |
| Colon with no block after `scene ... with t:` and `show x:`; screen property with no value (`focus_mask`) | `loose/syntax_loose.rpy` | parser leniencies (engine patch 0750) |
| `un.rpyc`, a compiled empty script under the name of a decompiler stub | `build.py` | `skip` of decompiler stubs |
| A file found only through the `images/` search prefix | `script.rpy` (`image synth logo = "logo.png"`) | Ren'Py 7 search prefix |
| A node that fails in Python 3 (`"cafe".decode("ascii")`) and its patch | `py7patch/` | patch library |

Not covered: `screen x:` with an empty block. Stock 7.4.11 itself rejects it ("screen expects a non-empty block"); only some
later 7.x versions took it.

`print` statements in `.rpy` Python blocks are not a case: Ren'Py 7 compiles those blocks with `print_function`, so the
statement form is a syntax error for stock too. It exists in loose `.py` modules only.

The runner also checks the player's runtime report of the probe launch (`check_compat` in `run.py`): it must hold a `rewrite`
event for each rule above, `syntax` events for the py2fix sites and the parser leniencies, a `fix` event for the ordering fix,
a `skip` event for `un.rpyc` and, for `Synth7Patch`, a `patch` event with `applied`.

### The port patch

`py7patch/patches/patch.toml` has a placeholder hash. The fingerprint of the script set and the hash of the node depend on
the `.rpyc` bytes, which differ between builds. `run.py` therefore starts the player once with the placeholder in the folder of
the game key (`PLAYER_PATCHES_APPLY_TEST=1`), reads the fingerprint and the node hash from `patches.json`, and writes the real
patch to a seed folder `patches/<fingerprint>/patch.toml` that the gate copies into the data folder (`--seed-data`). Without
the patch the player run fails at that node with `'str' object has no attribute 'decode'`.

## Notes on cases that were defects

- **Several failing blocks in one file.** `py7/game/rules_ordering.rpy` holds two failing `init python` blocks and two failing
  story blocks. `errors.fix_ordering` once keyed a fixed site by `co_firstlineno`, which is 1 for every module-level code
  object, so the second block counted as "fixed once and failed again". The key now holds the first line of the node's code
  block. `check_compat` expects four `fix` events.
- **`print >>f, x,` and a bare `print >>f`.** Python 2 writes the pending space of a trailing comma only before the next item,
  so `x` and a newline. The old rewrite wrote `end=" "` at once and left a space before the newline. A file with such a
  statement now goes through `_py2c_print`, which keeps the softspace (`loose/legacy_mod.py` covers `print >>buf, "d",` then
  a bare `print >>buf`, and a loop that prints with a trailing comma).
- **`Synth7Patch` `saveresume`.** The cause was the game, not the engine or the patch. The gate saves after `save_after` lines
  while auto-click keeps running during the settle time. The old script had 7 lines, so the save was made on the
  next to last line, and after the load only one line remained before the game returned to the main menu. The script has
  20 lines now.
- **Video check.** The gate used a synthetic clip for A/V sync on the assumption that corpus movies have no audio, and its
  warning ("game movie has no audio") was printed when `ffmpeg` was not on `PATH`, whatever the movie held. The `vp9_opus.webm` clip
  does have an Opus track (`ffmpeg -i` shows `Audio: opus, 48000 Hz, mono`). The check now uses the game movie when the movie
  channel reports an audio position, and builds the synthetic clip only when it does not. The clip is 20 s long (longer than
  the 3 s + 15 s window), because a 4 s clip that loops makes the unwrapped position lose about 40 ms per loop and the drift
  limit of 100 ms failed.
- **H.264 clip black on stock.** A stock limitation, not a mistake in the game. The clip is a valid Constrained Baseline
  H.264 file that FFmpeg decodes; the Ren'Py 8.5.3 stock engine draws nothing for H.264 whatever the file (see
  `research/py2compat-facts/README.md`, C2, where four real H.264 files from a commercial game gave the identical empty
  frame while VP9 and VP8 drew). The route plan marks the movie shots `volatile`, so a black H.264 frame on stock does not fail the gate.

Not in the gate: the rollback path of the ordering fix. With rollback allowed the player goes back to the last checkpoint and
the line before the failing node shows twice, so its dialogue hashes differ from stock. `rules_ordering.rpy` calls
`renpy.block_rollback()` to test the in-place retry path.

## Build

```sh
harness/testgames/fetch.sh            # SDKs (8.5.3, 7.4.11) into research/test-corpus/sdk/, OFL fonts into testgames/fonts/
nix build .#ffmpeg-synth -o /tmp/ffmpeg-synth     # LGPL FFmpeg with VP9, Opus, H.264 (OpenH264), Theora, AV1, WebP encoders
export FFMPEG_SYNTH=/tmp/ffmpeg-synth             # media.py refuses a GPL ffmpeg unless SYNTH_ALLOW_GPL=1
python3 harness/testgames/build.py                # every game into harness/testgames/build/<folder>/
```

- `build.py` needs only the Python standard library (Python 3.9 or newer). `gate.py` and `run.py` need Python 3.11 or
  newer (`nix develop` gives 3.12).
- The `ffmpeg-synth` package is the player's LGPL FFmpeg 7 (`ffmpeg-lgpl`) plus BSD-licensed encoder libraries (libvpx, libaom,
  libopus, libtheora, libwebp, OpenH264). It is a generator only; nothing links it.
- The Ren'Py 7 build runs the 7.4.11 SDK with `RENPY_DISABLE_BACKUPS`, a scratch `--savedir` and no display. It never writes
  the host save root (`~/Library/RenPy`, `~/.renpy`).
- Fonts: `fetch.sh fonts` downloads the OFL variable fonts Open Sans and Noto Naskh Arabic. Without them `text` still builds.

## Run

One command builds, runs stock, then runs the player against the stock result:

```sh
nix develop -c python3 harness/testgames/run.py --player-bin "$PWD/player/target/release/player"
nix develop -c python3 harness/testgames/run.py --games Synth7,SynthStory --player-bin /abs/path/player
```

For each game the runner runs `gate.py run --tier synth` (lint, probe, route, saveresume) once with the stock engine into
`harness/out/synth/<game>/stock`, then with the player into `.../player` with `--baseline .../stock`. Then the player run must
execute the same dialogue lines and draw the same frames as stock (route shot diff: mean 0.005, 0.5 % of pixels). `saveresume`
makes the save with the stock engine and loads it in the player, so the Ren'Py 7 games load Python 2 pickles made by
stock 7.4.11. Add `--baseline-root DIR` to reuse stock runs that CI keeps from an earlier job (stock results do not change
until the stock SDK or the game changes), and `--player-only` to skip the stock run.

Reference frames: the baseline is produced by stock in the same job, not committed. A committed window screenshot would depend
on the window manager, the display scale and the title bar. The committed references are the lossless image PNGs that the
`media` game generates (`game/reference/`) and compares in-game with every decoded format, and the expected values of the
Ren'Py 7 after-load checks.

Single gate commands (the corpus keys are in `harness/corpus.toml`):

```sh
cd harness
python3 gate.py run --engine stock  --game Synth7 --tier synth --out out/synth/Synth7/stock
python3 gate.py run --engine player --player-bin /abs/player --baseline /abs/harness/out/synth/Synth7/stock \
    --game Synth7 --tier synth --out out/synth/Synth7/player
```

Pass absolute paths for `--player-bin` and `--baseline`: the gate runs from the game clone. The gate takes the machine lock
(`/tmp/renpy_proj.run.lock`) for each launch; keep the pointer off game windows and send no input.

## Platforms

### macOS

Apple Silicon. The Ren'Py 7 SDK is x86_64 and runs under Rosetta. The gate captures only the game window
(`screencapture -l`). Use `nix develop` for Python 3.12 and the commands above. Metal is the player's GPU backend.

### Linux (artemis, real GPU)

The gate uses Hyprland and `grim`; the stock SDKs are dynamic ELF files and need `nix-ld`. See `harness/README.md`, Linux.

```sh
nix shell nixpkgs#python312 nixpkgs#grim nixpkgs#ffmpeg -c python3 harness/testgames/run.py --player-bin /abs/path/player
```

### CI on Linux

A GitHub runner has no GPU and no compositor. The gate has an Xvfb platform mode for it (`gatelib/plat.py`, class `Xvfb`,
selected with `HARNESS_DISPLAY=xvfb`). Per launch it starts an Xvfb on a free display (`-displayfd`), runs the game under a
whitelisted environment (`env -i` plus `HOME`, `USER`, `LANG`, a clean `PATH`, `DISPLAY`, a private `XDG_RUNTIME_DIR`,
`DBUS_SESSION_BUS_ADDRESS=disabled:`, `LIBGL_ALWAYS_SOFTWARE=1`, `SDL_AUDIODRIVER=dummy`), finds the game window by pid
(`xdotool search --pid`, `xwininfo -id`: read-only) and captures only that window (`xwd -id`, converted to PNG by the gate).
It sends no input. There is no window manager, so a window is never covered. Stock Ren'Py draws with Mesa llvmpipe (GL); the
player draws with Mesa lavapipe (Vulkan, wgpu). Optional variables: `HARNESS_XVFB_SCREEN` (default `1920x1080x24`),
`HARNESS_VK_ICD` (path of the lavapipe ICD JSON; Ubuntu finds it without), `HARNESS_GAME_ENV` (extra `NAME=value` lines for
the game, for example `RUST_LOG`).

Packages (Ubuntu 24.04; this exact list is the image the recipe was proved in, see "Proof" below):

```sh
sudo apt-get install -y --no-install-recommends python3 git procps util-linux ca-certificates \
    xvfb xkb-data x11-xkb-utils xdotool x11-utils x11-apps \
    mesa-vulkan-drivers libvulkan1 libgl1-mesa-dri libglx-mesa0 libegl1 \
    libasound2t64 libdrm2 libudev1 libxkbcommon0 libxkbcommon-x11-0 libx11-6 libxcursor1 libxrandr2 libxi6 \
    libxinerama1 libxss1 libpulse0 ffmpeg
```

`xdotool` finds the window, `x11-utils` has `xwininfo`, `x11-apps` has `xwd`. `ffmpeg` is the runner's, for the gate
video check only. Python must be 3.11 or newer (24.04 has 3.12). The corpus build needs the SDKs and the LGPL generator:
`harness/testgames/fetch.sh`, then `nix build .#ffmpeg-synth -o /tmp/ffmpeg-synth` (needs Nix; or `SYNTH_ALLOW_GPL=1` with
the distribution's ffmpeg for the media clips).

The player is the manylinux package (`player/packaging/manylinux`, glibc 2.28): build it with `build.sh` (rootless podman,
about 3 minutes with a warm cache, 25 minutes cold) or take the tarball of an earlier job. It leaves libstdc++, libdrm,
ALSA, udev, the Vulkan loader and X11 to the host, so the packages above are needed.

```sh
export HARNESS_DISPLAY=xvfb
harness/testgames/fetch.sh
FFMPEG_SYNTH=/tmp/ffmpeg-synth python3 harness/testgames/build.py
python3 harness/testgames/run.py --no-build --player-bin "$PWD/player/build-out/manylinux/player-linux-x86_64/player"
```

`run.py` runs stock and then the player for all seven games at the synth tier (lint, probe, route, saveresume) and exits 0
when all pass. Video: `python3 harness/gate.py run --engine player --game SynthMedia --tier full --only video` (the
SynthMedia movie is the source; needs `ffmpeg`).

NixOS (artemis) variant, no desktop session in the game: the gate, run under
`nix shell nixpkgs#python312 nixpkgs#xvfb nixpkgs#xkbcomp nixpkgs#xdotool nixpkgs#xwininfo nixpkgs#xwd nixpkgs#ffmpeg`, builds
`nixpkgs#mesa`, `vulkan-loader`, `libglvnd`, `libdrm.out` and `systemd` and puts them in `NIX_LD_LIBRARY_PATH` (not
`/run/opengl-driver/lib`, which would be the real GPU) and sets `VK_ICD_FILENAMES` to the nixpkgs `lvp_icd.x86_64.json`.
Run the whole job under `systemd-run --user --scope -p MemoryMax=12G -p TasksMax=500`: a missing session bus once made
libdbus start `dbus-launch` in a loop and the machine ran out of memory (the gate now disables the bus for the game).

Run time, measured on artemis (8 cores, llvmpipe and lavapipe use all of them): the Ubuntu container run of four games
(`SynthStory`, `SynthMedia`, `Synth7`, `Synth7Patch`, stock and player) took 582 s. All seven games on NixOS: the gate seconds
add up to 715 s for stock and 1073 s for the player; wall time for `run.py` was 1716 s (other jobs shared the machine lock, the
machine was loaded). Expect about 30 minutes for all seven games on a 4-core runner [INFERENCE].

#### Frames: llvmpipe (stock) against lavapipe (player)

The route check diffs the player's frames against stock. On the 49 route shots of the corpus, with the default thresholds
(`--diff-mean 0.005`, `--diff-pct 0.5`), the worst non-volatile values were: mean absolute difference 0.0044
(`SynthMedia` movie shots VP9, Theora, AV1: 0.0042 to 0.0044) and 0.40 % of pixels changed by more than 24/255
(`SynthView` `05-frames`; the movie shots 0.14 to 0.18 %); every other shot is below 0.002 mean and 0.02 %. Everything passes,
but the movie shots sit at 88 % of the mean limit and `05-frames` at 80 % of the pixel limit. The H.264 movie shot (99.8 % of
pixels, mean 0.41) is a volatile shot because stock Ren'Py draws a black frame for H.264 (see "Notes on cases that were
defects"); it is reported and never gated. The cause of the small differences is not isolated here [INFERENCE: rasterizer
rounding at 1 px frame edges and bilinear sampling for the pattern shot, YUV to RGB conversion for the movies, which also
differs on a real GPU]. Proposal for the CI job, for the synthetic corpus only: `--gate-args "--diff-mean 0.01 --diff-pct 1.0"`
(about twice the worst measured value). Do not change the real-game thresholds.

#### Proof

Branch `build/synth-ci`, player from the same branch (manylinux package, built on artemis), no GPU and no Hyprland session:

- NixOS, Xvfb, Mesa from nixpkgs: stock and player pass for all seven games (14 runs, `run.py` exit 0), synth tier.
- Ubuntu 24.04 in rootless podman (the package list above, the repository mounted, the host machine lock held around the
  container, Xvfb inside): `SynthStory`, `SynthMedia`, `Synth7` and `Synth7Patch` pass on stock and on the player
  (`run.py` exit 0, 582 s). The other three games use the same code paths and were run on NixOS only.
- Not run under Xvfb: the gate `video` check of `SynthMedia` (`--tier full --only video`).

The run found one packaging defect: the first manylinux package bundled `libstdc++.so.6` (GLIBCXX 3.4.25) in `lib/`, which the
player's RUNPATH put before the system one, so every Mesa driver failed with `GLIBCXX_3.4.29 not found`, wgpu found no
adapter and the player fell back to the software drawer ("this player draws with the wgpu renderer only"). It is fixed in
`container-build.sh` (libstdc++ is host-provided).

### Windows (WARP)

The Windows VM has no GPU; wgpu uses WARP, the D3D12 software adapter. The gate has no Windows platform module, so run the
player directly on the built game folders (build them on a Linux or macOS host, copy `harness/testgames/build/<folder>` over):

```bat
set WGPU_BACKEND=dx12
set WGPU_ADAPTER_NAME=Microsoft Basic Render Driver
player.exe C:\spike\synth\story lint
player.exe C:\spike\synth\story --data C:\spike\data --harness-script C:\spike\harness\rpy\zz_harness.rpy
```

`lint` is the headless check. With `HARNESS_DIR` set to an empty folder and a `cmd.txt` written by hand (see `harness/README.md`,
Plans) the injected driver plays the story and writes `progress.txt`. The Windows GPU gate is a recorded gap (M4).

## Files

- `build.py` builds the games; `run.py` runs them; `fetch.sh` fetches SDKs and fonts; `synthlib/` holds `gen.py` (PNG canvas,
  bitmap font, test card), `media.py` (ffmpeg) and `sdk.py` (Ren'Py 7.4.11 compile).
- Each game folder: committed sources in `game/`, `build.py`, and a route plan where the default one does not fit.
- Gitignored: `build/`, `fonts/`, `harness/out/`, `harness/work/`.
